## 1. 目标与范围

用户要求根据输入框的新含义重梳生成链路，随后补充DiceBear、MAAD-Face、CelebA、Avataaars的来源建议，要求正式写入「开源数据与词库来源」。本轮完成判断与记录，不把讨论或已创建规划模板冒充应用代码已修改，不安装依赖、不下载数据集、不新增模型费用、不操作业务页面或写生产数据。

输入框表达“想要什么样的人”，不是要求用户填固定字段的表单。系统先理解并保留明确要求，再在允许范围内补齐未指定人物特征，最后生成图片。仍是受控人物生成器，不扩成任意主题通用生图器。保留现有三栏、快捷条件、锁定、配置、不同人/同人造型、历史、收藏、下载及恢复。

## 2. 现状与需要修的断点

实际应用`src/lib/avatar-random/`已经具备词库、字段来源/锁、版本化Seed随机、约束、特征预算、批次差异和提示词编译。`catalog.ts`用重复选项表达部分权重，`engine.ts`按规则版本/Seed/计数哈希取样；本轮没验证为统计无偏，也不称所有属性已覆盖。当前没有独立胡须字段，鼻/唇/颧骨/眉毛/头发等已细分，不能再从零另建平行词库或一律新增重复字段。

`studio.tsx`输入后600ms的parse-status只查缓存/状态；非空文案首次prepare确认费用后才实际调用LLM。合法回复允许含unrecognized/conflicts，缓存仍可能标succeeded且前端隐藏成功状态；内核却因其中任一待解决项拒绝候选。再次点击复用同一缓存，可以重复报“尚未识别”。这是格式有效与条件就绪混为一谈的流程缺口，不是换随机库就能解决。

实际触发原文和那次完整模型回复未收到；不把通用源码条件冒充该文案精确根因。借鉴模型回复、校验结果和错误分离的[LangChain官方实际实现](https://github.com/langchain-ai/langchain/blob/master/libs/partners/openai/langchain_openai/chat_models/base.py)，复用既有私有回执/免费重新校验，不安装Python框架或增加自动模型重试。

## 3. 推荐的生成主路径

用户描述 → LLM理解并提取明确/排除/软条件 → 合并快捷设置与锁并核对问题 → 自有Avatar DNA结构及已许可词库 → 权重/冲突约束随机 → 提示词编译 → 图片报价与用户确认 → AI模型 → 原任务查询/结果保存。

| 阶段 | 用户可感知结果 | 关键边界 |
|---|---|---|
| 输入 | 原文和快捷条件安全保存，状态真实可见 | 打字、粘贴、刷新不自动收费 |
| 理解 | 简短理解摘要、必须保留、不能出现、可随机和待解决项 | 一次LLM同时给摘要和结构，不额外拆成两个收费调用 |
| 核对 | 显示真正生效条件，只处理重要冲突或能力限制 | 没指定不等于没识别，原文及已确认项保留 |
| 准备人物 | 四位满足条件、保留差异的人物信息 | 明确要求优先；随机只补未指定部分 |
| 报价出图 | 默认“1张四宫格，4位人物”的实际报价 | 四格各1人、不同人物、一次图片任务，不四次生成后拼接 |
| 等待 | 排队/运行/成功/失败/受理未知分开显示 | 查询失败不自动重发；未知受理只查原请求 |
| 使用/恢复 | 图片、历史、缩略图和余额同步；原快照能恢复 | 恢复、选择、查询不生成或扣费；保留旧图 |

推荐一个随阶段变化的主操作：非空文案“分析文案”后到“生成四宫格”；空文案跳过LLM直接准备人物和报价。首次或新的收费分析主动确认，不在输入停顿后隐藏发起；图片费用仍单独确认，可在现有确认层简要显示理解和实际参数，不再叠加一个“分析成功”确认。这里是方案建议，尚未改变现有页面触发方式。

理解结果展示结论，不展示隐藏思考、原始JSON或要求用户理解专业字段。例“25-35岁上班族女生，不戴眼镜，自然一点”：性别/年龄区间/无眼镜为明确条件，职场/自然感是软方向，未指定脸型五官发色允许随机。四格满足同一条件但不是同一张脸；“主角感”不能一律加伤疤。未指定位置不能编造来源；真正歧义/冲突只问该项，不要求重填整段。

最新明确输入 > 锁定 > 配置 > 软推断 > 随机；文案与快捷条件同层按实际编辑时间决定同字段生效值，同段原文内部矛盾要澄清。已理解但当前未支持的要求保留并说明限制，不丢到最终提示词外却声称已采用；默认写实适配与特殊风格是否兼容须实际核对。数量/排版与现设置有差异时展示差异，不能自动增加输出与费用。同人造型仍需独立单人真实参考，四宫格不能当单人身份基准。

## 4. 状态、缓存与恢复

用户状态分“未分析、分析中、需要补充、可以生成”；调用失败、格式错误和受理未知另行如实说明。LLM已回复、格式有效、条件就绪、图片已受理、图片成功不能相互冒充。有效但有未解决项的缓存应显示需处理，不再藏为成功后循环阻止生成。

| 变化/操作 | 应复用 | 需要更新 |
|---|---|---|
| 原文不变，换一批人物 | 已就绪分析与条件 | 新人物、提示词和图片报价 |
| 快捷条件/锁变化 | 原文分析 | 有效条件、受影响人物与报价，不必再调用LLM |
| 模型/画质/分辨率变化 | 已准备人物 | 能力/提示词与报价，不重新随机 |
| 自然语言含义变化 | 原文和快捷设置、旧结果 | 新草稿分析绑定失效；用户主动分析，不能静默收费 |
| 排版/人数变化 | 兼容规则及人物 | 数量/参考校验、必要人物补齐与报价 |
| 刷新/历史恢复 | 原条件、人物、参数、版本及原任务 | 查询真实状态；不自动分析/提交 |
| 原回复结构错误 | 私有原回复与草稿 | 免费重新校验，不称再次调用LLM免费 |
| 图片明确失败 | 原人物和提示词 | 仅失败项新付费确认；未知受理不得按失败重发 |

账号、文案内容、解析规则版本及当前草稿版本绑定分析结果；旧文案迟到回复不覆盖新输入。新草稿修改不重写进行中任务的原快照、不擦掉旧成功图；提交前确认报价对应当前条件/人物/参数。旧缓存兼容读取，不批量改生产数据或刷新时自动重解析。历史人物优先按已保存快照恢复，不能因新词库改变旧人物；重抽必须记录实际新词库和随机规则版本。
