## 1. 结论与边界

目标不是在网站放一个链接，而是让有权限的人能找到已有素材、继续加工、保存、送审、下载可复现的交付包，并把返工接回原任务。仍然是SD2现有后台里的一个工具，不再建另一套账号、项目或计费后台。

目前不能称为已闭环：本机工单覆盖单人加工主流程，尚不等于网站权限、资产归档、后台重启恢复及游戏导入已经成立。2026-09-28只读核对时，目标应用目录尚不存在；原工单仍记planned_not_started。本记录不推断其他任务是否已接单，不替它改状态。

| 层次 | 本轮判断 | 完成边界 |
|---|---|---|
| 本机首期 | 沿用原工单，不扩大范围 | WB01–WB06/V01–V10由原执行方交付；已有18条，不付费、不覆盖原件 |
| 网站接入 | 本文是待确认的实施建议 | 同一登录/项目权限、后台任务、私有资产、保存/导出/下载/恢复都通；仅加入口不算完成 |
| 游戏可用 | 另有明确证据门槛 | 确认真实tick率、坐标/锚点/纹理导入设置，在目标游戏导入同一包并有回执 |

建议先冻结输入/输出协议，允许本地处理内核与网站适配层独立推进；不要等本地页面做完才讨论数据。首期本地SQLite不直接复制进SD2数据库，生产动画记录由网站侧负责，处理程序只读冻结输入、返回结果，不直接写SD2业务表。正式网站不以浏览器连接操作者的127.0.0.1或Mac常开为隐含前提。

以下“应/必须”是实施验收要求。用户后续已授权落地，执行准备见第11节；这不代表新增的素材外传、权限扩大、生产数据覆盖获得授权。原有付费、覆盖、降质、越界停止条件继续有效。

## 3. 上下游闭环及责任

```text
已有素材/SD2视频资产
  -> 当前用户+项目核权 -> 冻结输入副本与来源
  -> 工作台选帧/锁帧/时值 -> 保存修订
  -> 冻结修订的处理任务 -> 临时结果 -> 完整性验证
  -> 正式版本包+项目资产登记 -> 预览/下载同一版本
  -> 固定素材审核 -> 游戏实际导入回执
                           |
               问题回到原任务，派生新修订
               受影响检查重新待审，旧包不覆盖
```

| 交接点 | 提供方 -> 接收方 | 交接凭据/失败出口 |
|---|---|---|
| 素材入场 | 素材方 -> 工作台 | manifest+实际资源+来源+授权范围；缺文件停受影响动作，不补假图 |
| 网站入场 | SD2 -> 动画模块 | 登录用户、项目及权限、受控asset_id；拒绝包内自报owner_id/project_id取得权限 |
| 处理提交 | 编辑器 -> worker | 已保存revision、冻结参数、输入清单、请求键；参数不合法在入队前说明 |
| 结果交付 | worker -> 网站存储/数据库 | attempt令牌、文件清单、校验结果；保存失败只补保存，不自动重做模型生成 |
| 资产入库 | 网站 -> 项目资产/下载页 | export_id、revision、完整包和审核状态；同一包重复登记不增生 |
| 素材送审 | 执行方 -> 三国审核01 | 冻结包、实际PNG、时值、必要播放证据；无回执就是未送达/待审 |
| 平台验收 | 网站实现方 -> SD2固定审核001 | 同版权限/恢复/页面/发布证据；素材审核不能代替网站安全验收 |
| 游戏验收 | 素材方 -> 游戏接收方 | 包版本、导入规格、真实游戏效果与回执；失败定位到动作/条目/原因，回到原任务 |

不建第二个问题账：素材问题继续写三国`tasks/review-issues.md`的AWB条目；网站问题进入SD2现有待办/固定审核记录，互相引用问题ID。

## 5. 数据协议与状态建议

下列是拟议契约，不是现有API字段承诺；INT01确认后才固定接口命名及schema。

- 输入：schema_version、来源/校验、动作条目及hold_ticks、tick_rate及其证据状态、pose与entry映射、PNG纹理尺寸、逻辑画布/倍率、坐标原点/轴向/锚点、候选索引与PTS、用户认可和历史问题。服务端单独绑定真实用户/项目，导入内容不授予权限。
- 编辑：animation_id、revision、mutation_id、entry选择/锁定、显式变换及理由。保存和撤销产生修订；拒绝旧修订无条件覆盖；只有选定动作参与本次处理。
- 任务：job_id、revision、输入/参数摘要、stage、attempt、lease、错误码、可否重试、时间戳。数据库事务不包含长时媒体处理；取消不等于删除。
- 交付：export_id、schema/应用/处理器版本、不可变文件清单与必要校验、entry_count、total_ticks、预览tick假设、检查结果、审核回执与游戏导入状态。worker结果通过校验后由网站登记资产，不直接信任worker提供的任意路径。
- 资产引用：源视频与冻结副本分开；母帧、选定PNG、包、预览各有用途。底层内容去重不合并播放条目，也不改变所属项目授权。
- 接口表现：提交返回可追踪ID；状态查询返回阶段和结果就绪条件；保存冲突明确返回当前修订；素材接口经过相同权限判断；断网重试用原请求键。不得从一次创建响应猜最终结果。

推荐分别显示：保存状态（保存中/已保存/冲突）；处理状态（排队/运行/中断/失败/取消/完成）；交付状态（归档中/归档失败/可下载）；检查状态（待检查/有问题/通过）；游戏状态（未验证/待修正/已验证）。不用一个包含所有组合的巨型状态字段。

页面主路径：现有创作入口的“抽帧动画” -> 选择有权限项目/已有素材 -> 选帧及同步检查 -> 保存/处理 -> 项目内版本结果 -> 下载/送审 -> 问题定位原条目。查看者是否可下载、编辑者是否可送审由INT01明确，不机械等同于页面可看。普通用户不进入API设置页。
