## 目标和用户证据

用户在正式站图片模板页再次看到“图片服务已返回链接，但下载未完成（download_total_timeout）。冻结积分已释放；重新生成会再次请求上游”，要求查根因和评估能否救回。浏览器评论附了一张截图，标记失败结果卡片；本线程没有拿到该截图可复制的本地原件路径，不能声称已归档。复现和定位以正式服务器任务、日志和源码为准。禁止为排查而重新发起付费生成。

## 只读调查结论

- 本次任务 `90484fcde8dc4dde69415fb734d328bff1ce4d116ced289151166f73f2ea4563-0`，2026-10-01 13:35:37 北京时间结束，状态 `uncertain`，没有 `asset_id`。同一请求批次仅这一张；同一用户/提示词/上下文未找到另一份相同任务，资产表也没有按该任务命名的文件。
- `systemctl status sd2-image-studio.service` 的真实 worker 日志：阶段 `download`、HTTP 200、已接收 1,179,648 / 4,752,867 字节、耗时 180,011 毫秒、`download_total_timeout`；从任务开始到报错约 241 秒。当天 08:39 的另一张同模型图片也在 HTTP 200 的 body 阶段触发同样 180 秒总时限，已接收 12,189,696 / 12,235,926 字节，显示故障可在接近完成时出现。
- 正式服务器 `/srv/video-api-debugger/app/src/lib/image-studio/media.ts` 对 URL 图片下载设定固定 180 秒总时限；`provider.ts` 在内存里读取上游返回的 URL，再将完整图片交给 worker。URL、已下载片段和上游响应没有持久化；总时限到达后不重试该 URL，任务被标为 `uncertain`。`worker.ts` 仅记录阶段/字节/HTTP 状态等脱敏诊断，不记录 URL。
- 积分账本对本次任务有 `task_freeze -20` 与 `task_failed_refund +20`，站内积分已退回。`provider_cost_usd` 是提交时的模型成本估算，不代表已核实上游实际账单。
- 确认的断点是“上游已给出可下载 URL 且 HTTP 200，但本站未在 180 秒内收完 body”。网络/图片托管端为何低速或停顿尚未查明；因为 URL 主机及下载进度曲线没有留存，不能断言是上游服务器、特定 CDN 节点或本站出口哪一方造成。
- 本站目前没有这张图的完整副本、可续传片段或已保存 URL，无法从本站直接救回。唯一待核实的外部途径是 Musk APIs 后台/支持方是否保存此次图片及可再次取得的链接；未发现可核实的公开结果查询接口，勿猜测端点或重放生成请求。

## 待执行工作

- [ ] T1. 在上游后台或其正式支持渠道仅查询此次请求是否仍有可取回原图，按时间、模型和请求特征定位，不外发完整提示词、参考图、密钥或生产数据；如需联系第三方/提交敏感信息，先取得用户对具体内容和收件方的授权。找到 URL 后先确认未过期且权限正确，再在可控链路下载并校验完整字节/图片可解码，最后按用户许可关联到原任务；不得修改历史账本为“成功”却没有图片。
- [ ] T2. 核对正式版下载实现及近两次超时日志，确定服务器到实际图片域名的吞吐、停顿位置和 URL 有效期；只记录域名、时间、字节、状态，不记录签名 URL。比对最近成功与失败样本，避免仅机械增大超时时限。
- [ ] T3. 设计并实施不会重复付费的交付恢复：上游返回 URL 后安全持久化恢复所需信息（受限、加密或等效保护、短期有效），下载使用受限流式临时文件/校验、超时后同一 URL 有界续传或重试、明确过期与清理；任务租约和积分状态与交付状态相符。若无可恢复 URL，则继续标记未交付，不能自动重发生成。现有 20MB/生成大图上限、SSRF 防护和鉴权不得削弱。
- [ ] T4. 完成定向模拟慢速/中断/接近完成/URL 过期/重启恢复验证，不调用付费模型；然后聚焦提交、推送、候选构建、服务/公网检查和回退点，部署后由用户手动功能验收。保护当前工作区并行脏改和线上持久数据。

## 停止条件与回执

上游没有可查询原图能力、结果链接已失效、下载文件不完整或身份无法核实时，明确报告“无法救回这张原图”，不得用重新生成冒充恢复。任何付费重试、给上游发送私有资料、覆盖生产资产或改账本前先确认。执行者回执需分开写清本次图片是否救回、根因证据、代码/部署状态、站内积分与上游费用是否已核实；上线用“已部署，待用户手动验收”，不能把健康检查当成功能验收。
