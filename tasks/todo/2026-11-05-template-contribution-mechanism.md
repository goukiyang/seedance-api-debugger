## 1. 一分钟看懂

**制度长期存在，预算按月管理，真正持续帮到同事的模板可以持续获得奖励。试运行只验证规则，不决定制度寿命。**

推荐基础规则：一个模板来源，每自然月最多获得一笔“业务复用奖”。当月至少一位作者之外的同事，用它完成了新的真实工作；系统汇总原任务和结果，管理员独立核准后，发到作者原有点数账户。

同一个好模板，下月仍实际帮到了同事，可以再次获得奖励；不要求为领奖故意改版本。只发布、点赞、收藏、自用、反复点击生成，不直接发点。同月换项目、换版本、复制模板或增加生成张数，不增加奖励次数。

这里“积分”就是原有可消费点数，不再创建一种兑换币，也不开放转账、提现或同事间买卖。贡献次数是事实统计，不是待兑换余额。制度、预算和发奖尚未启用。

## 3. 最少的奖励参数

| 参数 | 当前设计 |
| --- | --- |
| 制度期限 | 长期，直到明确调整或停止；不是每月重新发起活动 |
| 贡献月份 | 公司口径Asia/Shanghai自然月，以原任务服务端受理时间归属；实际时间戳仍存UTC |
| 每模板每月基础奖 | 200点，**仅用于试算，未批准** |
| 每人每月上限 | 2,000点，**仅用于试算，未批准** |
| 全站每月预算 | 20,000点，**仅用于试算，未批准** |
| 预算来源 | 平台批准的内部奖励额度，不向使用者额外收取模板费，不挪用项目生成预算 |

全站月预算应在被批准的额度/有效期内按既定周期续开，不必让员工每月报名；未获授权的未来月份不得自动拨款。月预算未批准或暂停时仍可正常创作、记录贡献，但不能把记录显示成已赚奖励。

预算、奖额与个人上限对之后的月份生效；本月允许明确追加预算，不回溯降低已公布的奖额或已预留承诺。紧急暂停停止新核准，已承诺款项保留，恢复与补登沿原记录，不换号发钱。

基础工作配额独立保留，不发布模板、无人复用或未获奖都不因此降低原有工作额度；不让员工先赚奖励才能正常完成工作。

1元=100点仅为站内口径。每月20,000点、持续12个月是240,000点，即2,400元名义额度，**不是供应商实扣预测或成本上限**。模板奖额也不是生成费率，不从供应商账单反推作者应该赚多少。

## 4. 有效业务复用怎么认

- 有效内部账号均可贡献，不按核心/非核心岗位决定领奖资格。既有共享模板和新模板同等参与；不追溯制度启用前的旧任务。
- 模板需有用途、适用输入、效果样例、已知限制及合法可共享素材。只在现有授权同事范围共享，不为领奖强制全公司公开或开放原图。
- 至少一位受奖作者以外的同事实际使用；原任务有真实可用交付且站内结算明确。个人余额、周期配额或项目预算支付都可，零费用合法产出也不因此失去资格。
- 有实际工作采用记录：可由使用者在原结果处标记“用于工作”、关联已有交付或补一句用途；已有负责人采用记录直接复用，不要求再填表或重复确认。生成成功、自动进入项目、下载或收藏本身不等于采用。
- 个人/默认项目也可能有真实工作，正常业务项目也可能有测试；仅凭项目名称、付费多少、IP相同或同事互相使用不能自动认定有效或作弊。
- 只认服务端冻结的主模板来源。纯手动复制、缺可信来源的旧记录和附属风格/素材不猜受奖归属，不做多层分成。
- 同一任务/批次只保留一份贡献事实，部分成功只认合法交付和明确结算部分；失败、取消、调试不合格，未知继续核原请求，不推断免费或自动重发。
- 对同一模板来源，同月无论几个同事、几个项目、几批图片或几个版本，最多一笔基础奖。下月必须存在新受理的有效工作任务，不能重交上月任务、旧结果或旧采用标记。
- 发布、回复、维护、收藏可形成非金钱贡献反馈，但第一版不叠加维护奖、拉新奖、签到奖或消费返利。稳定好模板不必故意改版；缺实际复用也不因改版自动领奖。

## 5. 身份、来源和长期维护

每个模板来源登记一个受奖人，共同创作者保留署名，不在第一版拆分奖金。月初冻结本月受奖登记；新来源在首次参与时登记。经确认的交接从下月奖励登记生效，不改变即时编辑/管理权限，也不自动重分已承诺或已到账奖励。有归属争议仅暂缓该项，由非受益管理员沿交接证据处理，不以先点击抢到为准。

官方/系统模板不默认计作管理员个人贡献；管理员本人创作也必须有真实受奖登记并由另一位获授权者终审，管理身份不增加奖励资格。

基础奖选择“同来源每月一次”是为便于理解，不代表一次小范围采用与大量关键复用价值相同；它不按调用量加钱，也可能仍诱发拆模板凑数。首阶段用来源核实和真实用途限制，不声称已经解决语义拆分。是否增加少量精选奖励，须先有持续复用和实际收益证据，不在本轮自动叠加新奖种。

复制、另存、改名和普通版本更新沿同一来源族；公开编号或新ID不是独立贡献证明。真正独立的新模板可以重新登记，但需核实际差异，不能声称简单哈希能识别语义抄袭。来源族服务端关联尚需后续实施，不能仅相信客户端传的rootId。

新模板应有可被发现的展示位置，与常用模板并存；先复用现有目录/作品入口并做人工轮换，不新建推荐算法或要求先有大量使用量才能开始。反馈就地关联原模板，让作者知道适用失败原因并能改进；不把低评分、合理投诉当扣点依据，不把个人消耗榜当贡献榜。

正常撤回或停止维护只停止后续新参与，不抹掉历史合法贡献；侵权、泄密或伪造采用另行暂停核对。禁用、离职或删除账号走原保护路径，待到账部分挂起，不转给接手人；已到账记录不因账号状态变化删除。

## 6. 反馈、核准与预算不足

正常路径：同事完成工作 -> 自动记录贡献并合并同月同来源候选 -> 原结果留下采用依据 -> 管理员核准且预留原月预算 -> 原账户到账。

- 作者不用逐次申请奖励，也无需替系统填写任务ID、账单或来源。有效交付确认后即反馈“本月有N位同事复用”，不先显示“已赚200点”。
- 管理员复用现有管理入口按周批量核准，查看模板、可访问的结果摘要、用途、受奖人和真实差异；异常才补佐证。周处理是运营目标，不是已经配置的定时器或响应承诺，需落实责任人和获授权的替补。
- 受益人不得终审自己的奖励；没有独立获授权的审批人就暂缓该项，不临时扩权。批量操作逐项返回成功、重复、预算不足或待补充原因，失败项不让已成功项重发。
- 未核准时显示“贡献已记录 / 待核准”，不是可提现、可兑换或已承诺余额。只有资格和原月预算预留同时成功才显示具体“待到账”数额。
- 全站及个人月限额均计算该月已发放+已预留。可核准候选按进入完整证据队列时间处理，不以管理员点击顺序或作者催促排序；存疑项不占无期限的候选预算，也不冒充已获奖。
- 预算或个人上限不足时整笔不核准，不缩水、均摊或自动借下月预算，明确“本月额度不足，尚未核准”。追加原月预算可以原记录重新核对，不能重新生成凑资格；下月有新真实贡献才按下月规则评定。
- 发布规则时公开适用条件、月额度状态和到账处理节奏，预算接近上限只提醒负责管理员处理，不催普通同事消费或制造抢奖倒计时。
- 已核准奖励正常处理目标为次日到账。服务故障或账号异常展示原状态及负责角色，不自动拒绝、丢队列或要求作者重复申请；未知回执只查原号。
- 人工核准仍可能误批，低成本互刷风险没有被数学消除；按真实采用依据、来源关系和必要抽查处理，不因办公IP相同或合法合作直接处罚。

## 7. 跨月、原账和错账

贡献月、核准时间和到账时间分开保存。例：11月30日23:59（公司时区）受理，12月才完成或核准，仍是11月贡献；不能拿同一任务再次申领12月奖励。12月有新的真实工作复用才可另评。

- 月末停止向旧月追加新受理事实，建议次月前7天做常规结账；超出窗口的未知/迟到事实保留待核，不自动判失败或失去原记录。
- 已预留的旧月承诺一直归旧月额度，跨月支付不挤占新月预算。未用预算不自动滚入下月；旧月补登需原月仍可用的授权额度和原月个人上限，已回收的预算须明确补充核准，不暗中占下月额度。
- 贡献月份唯一键为`template_root_id + contribution_month`，不包含活动ID、任务ID、版本或受奖人。新月份可有新奖励，但同一原任务的月份不随处理时钟改变。
- 上述是奖励唯一键，不替代原任务/批次贡献事实的唯一记录。月份、来源及受奖登记取服务器原事实，不能由客户端改日期或换操作号生成另一份贡献；各生成入口的实际去重映射须在实施前核实。
- 核准事务原子保存唯一奖励事实、原月预算及个人限额预留；付款事务原子转换原预留、更新原长期余额、写关联流水/原回执。外部通知在事务后沿已有outbox处理，不靠页面计数或先加余额后补流水。
- 同一操作重放返回原回执，篡改原内容拒绝；换操作号重复申领仍受业务唯一键约束。付款请求未知只核原记录，停用新规则或程序回退不抹账、不重新发放。
- 已到账点数进入原长期余额，月底不清零，优先消耗临时额度的现有顺序不变。奖励不自动扩大模型、项目、素材或高清审批权限；个人奖励也不自动变成任意项目的可用预算。
- 一次奖励发放只记一次内部额度分配；任务真实供应商成本仍计原生成项目，不把奖励再当作该项目API支出。原奖励点数不因后续费率调整重新换算或改数。
- 长期余额资金已混合，第一版不能准确声称“奖励还剩多少/哪次任务花了奖励”；只展示真实累计发放、冲正、待到账、账户余额和供应商实扣，不新造一套资金桶来填这个数字。
- 纠错追加关联原流水的冲正，不改旧账；冲正不自动重新开放本月获奖资格或已用预算。余额已用完不自动扣负，未追回差额和处理决定如实保留。未支付预留撤销可有原因释放原月额度，但原取消回执保留，普通重试不能绕过。
- 奖励争议按具体记录提交一次，管理员给出理由及原记录复核结果，不要求重新发布、重生成或重复申请。支持正常改进，不承诺用自动规则判断所有抄袭和虚假采用。

## 8. 用户实际看到什么

| 位置 | 常显与主操作 | 按需或异常 |
| --- | --- | --- |
| 模板目录/详情 | 用途、效果样例、使用入口；本人可看本月贡献与奖励状态 | 适用条件及来源说明展开；不把所有限额塞满卡片 |
| 生成结果 | 正常查看/继续使用；工作采用可就地标记 | 不强迫评价或先申请奖励，不改变原报价和生成确认 |
| 个人贡献入口 | 本月复用同事数、待核准条数、待到账和已到账；可切贡献月份 | 具体记录显示未核准/预算不足/账号异常原因与复核入口 |
| 管理入口 | 真实月预算、候选、责任人、批量核准及逐项结果 | 原任务/采用证据按权限展开，旧月补登与冲正低频操作保留 |
| 原点数流水 | 模板奖励来源、贡献月份、实际到账时间 | 查看原回执；不额外建一个与原余额对不上的钱包 |

作者不得因领奖看到他人私有提示词、原图或项目详情；只显示获授权的摘要。复用同事数按非作者、已交付且结算明确的任务按月去重，不含未知/失败/自用，不等于业务采纳或奖励资格；缺数据不伪造0。待核准只显示条数，不与已到账合成“已赚”。贡献页按贡献月归属，原流水按实际到账时间展示，迟到款标清两者。小屏、键盘及返回保原现场，批量核准不因选中变化丢失结果。

## 9. 衡量、试运行和实施顺序

长期闭环：需求和样例被发现 -> 同事复用 -> 真实工作采用 -> 作者收到及时反馈与经核准奖励 -> 作者维护或创作 -> 下月仍可凭新贡献继续获得回报。

第一步先确认本规则和奖额/个人上限/持续月预算授权，并校准200点在常用生成报价下的实际用途及作者投入。数字未定不影响本轮完成设计，但不能据此认定实施已具备所有业务前提。

第二步只记录不发，验证来源、去重、真实工作采用及审核负担。事先写清这一阶段不自动产生补发承诺，旧模板可参与之后的新贡献；不偷偷启用、不把试运行日期当制度失效日期。

第三步在明确参与范围启用同一长期规则，不另造活动版和永久版两套账。核对贡献反馈、核准、到账、消费权限、原流水及跨月补登；业务前提或真实账务验证缺失不进入自动发奖。

第四步按月复盘真实参与作者/使用同事、业务采纳模板、跨月持续复用、审核工时/申诉及供应商实际成本。制度没有规定每月必须改规则；样本小或缺基线只报观察，不宣称提升。金额不够或核准太慢先定位原因，不靠加奖刺激更多API消耗。徽章、精选、主题挑战可后加，但不替代基础规则，也不先叠多种可兑换币、签到或多级返利。
