# 团队作品广场规划概要

日期：2026-11-02。规划R02。状态：规划缺口已修订，可见范围讨论中，尚未实施。

目标是在既有应用内提供登录后的图片／视频作品浏览、查找和收藏，并在内容增长后分别控制查询、页面挂载、媒体请求与缓存工作量。

采用方向：统一轻量作品查询与必要目录、TanStack Virtual、已有媒体组件和权限能力。保留原有生成、文件及业务记录。

## 任务顺序

- [ ] TW00 核定执行时实际版本及作品可见范围；该范围仍在讨论。
- [ ] TW01 建立逻辑作品与输出版本、来源关联、耐久增量收录和生命周期状态。
- [ ] TW02 完成按权限过滤、前后游标、锚点定位和轻字段页查询。
- [ ] TW03 接通作品级成品媒体授权，复用缩略图、视频封面和播放协调，缺失派生后台补齐。
- [ ] TW04 接入响应式虚拟瀑布流及作者／项目／类型筛选。
- [ ] TW05 完成详情、版本变化接续、有权者撤回入口和浏览现场恢复。
- [ ] TW06 完成混合作品收藏、持久化和分页读取。
- [ ] TW07 完成候选必要工程／安全门和手验材料，保留用户手验与性能待测状态。
- [ ] TW08 在后续实施阶段按现有流程保护发布与恢复。

依赖：TW00→TW01→TW02／TW03→TW04→TW05／TW06→TW07→TW08。

可见性讨论应分别确定访问范围、广场／搜索展示、下载与参考权限。默认范围改变不自动扩大旧私有内容。产品案例可参考 [Canva 团队分享](https://www.canva.com/help/team-sharing/)、[Frame.io 权限](https://help.frame.io/en/articles/9875389-user-roles-and-permissions)、[Pinterest 私人画板](https://help.pinterest.com/en/article/secret-boards)。这些案例不代表项目已采纳对应政策。

## 规划审查补齐的六项合同

1. 列表可见与媒体可读接到同一作品及版本，原有其它权限不扩大。
2. 本人隐藏、移出广场、共享撤回与来源失效分别表达，后台补录不复活已撤回作品。
3. 逻辑作品保持稳定，收藏／普通链接指向当前发布版本，正在进行的操作固定已读版本。
4. 收录可从耐久成品事实恢复，失败和重启可接续，不依赖一次内存回调。
5. 数据缓存淘汰后仍可按锚点和前后游标回看，新增内容与权限变化有明确处理规则。
6. 工程门就绪后保护部署，用户功能手验在发布后；备份保留不可重建的集合、授权、撤回与回执。

以上是规划修订结果，不是软件已经实现或验证。默认受众、发布／撤回操作者等仍待讨论，原历史及已受理／未知请求不自动扩大范围。
