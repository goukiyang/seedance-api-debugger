## 3. 最终设计

### 3.1 原图与生成设置

初次使用保留完整设置区：左主图，右方案、参数、补充要求、高级设置；底部归属与生成。已有有效结果后沿用户展开偏好，收为一行“主图缩略图＋模型/时长/清晰度＋修改生成设置”，不要自动抢焦点或强行关闭用户刚展开的设置。

- 主图保留更换、素材选择、拖入、粘贴和真实上传状态；未知上传沿原请求恢复，不把收起当上传完成。
- 生成方案选择器与“保存设置”相邻；保存按钮主区保存当前本人方案，下拉含“另存为设置”和恢复默认。初次保存/另存命名及共享沿原产品弹层；他人方案不能覆盖，只能另存。新方案默认共享给现有授权同事，用户关共享后后续保存保持私人。
- 模型、时长、清晰度同排；补充要求常显；比例、seed、音频、末帧、水印、完整提示词等原能力放高级设置，不能删。管理员“模板提示词”保留明确管理入口和原服务端权限。
- 项目必选且实际可用；视频卡可选。刷新、新建项目/卡入口归入项目选择旁的小菜单。1080p的原审批条件出现时就地显示，不藏进“更多”，不借无卡绕过。
- 生成按钮旁显示当前真实报价及报价加载/失败；参数改变后旧报价不能伪装当前价。保存方案不生成、不收费，不成为生成前置条件。
- 预览图里的0/500、示例模型/8秒/480p/项目名称不是新限制或默认值；沿实际能力与剩余提示词长度。移除图中红色必填星号，普通待补用正常文字。导航和头像沿真实项目，不照搬生成图占位内容。

### 3.2 生成阶段与旧作品分离

保留用户要求的横向连线阶段设计：“提交 → 等待生成 → 生成视频 → 准备选帧 → 可以选帧”。这是明确的阶段轨道，不按时间填充、不按阶段等分冒百分比，不显示虚构排队人数、剩余时间或供应商进度。已知真实数值（例如补清晰画面3/8）只表示该局部任务，不冒充总体进度。

| 真实输入 | 主文案/阶段 | 可做什么 |
|---|---|---|
| 正在发送原请求 | 正在提交 | 保输入，防重复；不以本地taskId认定供应商已接单 |
| 原请求未知、无有效原任务或submission_unconfirmed | 提交结果待确认 | 只查原请求；保原key/费用/关闭回执保护，不转成失败或换号重发 |
| 明确供应商queued/pending/created且原受理身份有效 | 等待生成 | 可编辑下次设置；原任务参数冻结 |
| 明确running/processing/in_progress且原受理身份有效 | 视频生成中 | 同一轮询；不把未知状态映射出来的local running当实际开始 |
| 供应商状态不认识或查询暂断 | 状态暂未确认 | 保上次已确认阶段并标暂未更新，无确认则不亮生成中；查询原任务，不重置计时/自动重发 |
| local succeeded，但原片/交付未可读 | 正在准备视频 | 进入准备阶段下的实际子步骤；尚不能显示“可以选帧” |
| 原片info有效，正在准备预览 | 正在准备选帧 | 立即在await前反馈；图集准备无内部百分比，保旧作品可用 |
| 当前新源首组有效可选画面已就绪 | 可以选帧 | 没有旧作品时进入；正在编辑不同作品时提供“打开新结果”，不自动覆盖。原图未齐另走MV-HD局部补清晰，不锁轻预览 |
| 明确failed/cancelled/拒绝 | 本次生成未完成 | 保素材/草稿及原错误；具体可恢复入口常显，不伪称退款或免费 |

实现选择：扩展现有TaskStatus读取字段白名单（provider_status、provider_task_id、provider_client_request_id、created_at、delivery_status及已有身份字段），在多视图本地纯映射函数产生展示状态；字段已由现有serializer输出，不新增状态接口，不改共享finalizer、供应商映射或账务语义。缺字段/旧客户端按未知处理；不展示raw响应、凭据或费用内部结构。provider_task_id若是本地/客户请求号占位不当真实受理证明。

计时取服务端created_at，标题“提交后已用时”，不是“实际生成耗时”；缺失就不猜。旧作品和本次新生成分别绑定taskId/key/sourceVersion；旧作品ready不能把新任务轨道标满。仅打开已有视频不重播生成轨道。完成后压缩成结果摘要，查询暂断/失败仍有可达入口；详细状态从“详情”按需打开，普通等待不红字、不弹窗。

### 3.3 大拼图与操作归位

- 以完整图片为主，不裁切、不把工具条渲进PNG/ZIP。顶部一行作品名（点编辑）＋真实保存状态；下方一条工具栏：选帧/排版、3/4/8张、选帧方案、保存方案、查看原视频、更多。
- 默认选帧视图不再常驻每格名称输入、长帧信息、重复缩略条及重复侧栏。逐格选择在大图完成；名称改为格内铅笔入口，帧信息和操作在情境工具条；所有原能力按下表迁移，而非删除。
- “换帧”打开同一工作区的紧凑编辑面板，桌面靠当前格右侧/下侧并避让，窄屏用项目抽屉；需要播放器和邻帧等多项内容，不能塞进tooltip。保单大预览、原视频/循环、时间轴、邻帧、±1/±10、指定帧、放大、应用/取消。普通关闭和Esc取消未应用选择、回原格，不生成。应用成功关闭面板；失败保面板和输入。
- 排版tab才显示列数、间距、边距、背景、重置等现有选项；选帧/排版切换不丢选择。3/4/8沿reserve与撤销规则，不静默删除隐藏帧。拖图片只排序，不换原图；拖控制条只选帧。
- 更多保留另存一份、撤销/恢复顺序、清除当前工作台等低频入口；撤销有变更时在工具栏给小图标快捷入口。清空与普通切换的确认规则不混同；无实际不可恢复损失不加二次确认。
- 查看原视频保留现有放大尺寸（桌面目标高520px、窄屏受可用宽高约束contain），不重新缩回260px；循环初次默认开、已有个人关闭偏好优先。循环键和必要说明同排，不各占一行；视频实际版本/轮次/类型保持可查，未知不造值。自动恢复暂停，不擅自播放。
- 底部固定栏只保“尺寸/可用数量＋复制拼图＋下载拼图▾”；菜单有单张ZIP及已有合法导出能力。准备、失败、部分就绪时以真实数量和安全出口反馈，不冒充全部就绪。保已有ResizeObserver/底部安全区占位，不能挡最后一行或手机键盘。
- 同一作品默认自动保存最后修改，只有明确“另存一份”才branch。已保存配方、服务器成品待准备、成品ready分别表达。保存失败/冲突/原保存未知保原回执及本机草稿，不用另存掩盖失败；首次作品仍本人私有。

### 3.4 新增每格悬停滑条（确定方案）

桌面鼠标进入图片或键盘聚焦该格时，底部浮出两行紧凑控件；离开且无焦点/拖动/打开子层时隐藏。只有选中描边不让工具永久常显。触屏轻点图片显示当前格工具，再点其它格切换；滚动或拖图排序不误当轻点。不要把全部格控件常显作为移动端兜底。

```text
┌────────────── 当前格图片 ──────────────┐
│                                      │
│  ───────────●──────────────────────   │  快速选帧
│  正面 ✎   第32帧 · 1.292秒  ‹  › 换帧 ⛶ │
└──────────────────────────────────────┘
```

线框仅说明层级；用项目lucide图标与真实尺寸，不画新图标。轨道细，但命中区桌面至少32px高、触摸约44px；紧凑格适当把名称移入编辑入口，不挤到无法拖动。工具绝对定位、不改变网格高度，底色保证可读；保图片完整contain，临时遮挡可在移开后消失。名称/帧号不是常驻占行。

**范围与语义**：原生`input type=range`，min=0、max=timestamps.length−1、step=1。每格独立映射当前视频完整帧范围；内部0起算、界面1起算，秒数用真实timestamps，不能按假定24fps换算。单帧视频禁用滑动并说明；未知info不造范围。保左右±1快速键和精确换帧入口。

**一次手势的事务**：

1. pointerdown保存当前账号/权限epoch、taskId、sourceVersion、槽位id、原帧及draft基准；调用pointer capture，将滑条与图像排序激活区隔离，不把input嵌进button。
2. onInput/onChange只改临时target，不改正式draft/作品签名，不触发保存、PNG提取或服务端生成。requestAnimationFrame合并输入；同一时刻最多一个轻预览编码/解码任务＋一个“最新待处理目标”，丢弃中间排队项。沿现有320像素JPEG图集、块缓存、请求去重，不批量预取整条时间轴。
3. 暂停MV-HD的低优先级排队补齐，已开始的共享原帧请求不强杀。拖动优先用轻预览；缩略读失败不在每次输入退化成原PNG提取。未准备好的目标保上一张已显示画面，就地标“正在预览第N帧”，不能给旧画面配新帧号冒充已经显示。
4. pointerup捕获最终value后只提交一次。最终轻预览可读且上下文仍一致才`update`当前槽位frame/manual，原名称、顺序、reserve不变；一次手势只留下一个撤销点。与原帧相同不产生保存或撤销。若最新目标仍冷加载，保持局部待准备，不提交中间帧；失败回原选择并给重试。
5. 提交后清临时态，由MV-HD约200ms停手调度补该格原尺寸，当前格优先，保单路/缓存预算/解码后替换；作品沿原750ms聚合保存同一id。连续几次手势仍合并到当前作品，不创建多份。
6. Escape、pointercancel、非预期lostpointercapture、切任务/源版本/账号、失权取消未提交手势，废弃迟到响应，不写作品；正常pointerup之后的lostpointercapture不能反过来撤销已经提交的目标。失权按原机制清理，不能以保留旧图绕过。
7. 拖动或最终提交等待时工具条固定可见；移出格外仍能拖动/松手。只阻止会读写同一配方的排序、方案应用、3/4/8、另存、复制/导出及第二格并发手势；不锁无关生成设置或整页浏览。主动切任务取消临时手势，已提交未知保存仍按原保护。
8. 键盘Tab聚焦显示，方向键±1、Home/End到端点、PageUp/PageDown±10；按住重复只预览，keyup提交一次，Tab离开提交最终有效值，Escape撤销本次。辅助技术无pointer事件的变更沿input＋短空闲提交（200ms），不依赖pointerup唯一出口。aria-label带槽位，aria-valuetext带真实帧/秒；不在每个滑动像素通过live-region读屏轰炸。避免手写键盘更新与原生默认双加一次。

### 3.5 保存、返回与小屏

生成草稿、偏好、选帧draft、作品绑定仍走现有账号/对象/源版本键。只有已提交帧进入持久记录；未提交的拖动位置、鼠标悬停、指针锁不跨刷新恢复。显式taskId/workId链接优先，失效条目安全说明，不跳到其它作品。重置浏览设置入口保留，不误清媒体/作品。状态反馈只作用当前对象，普通错误不红字，不把详细错误日志常驻。

桌面双列设置，小屏主图后接必要参数，低频项折叠；拼图工具栏允许有限换行，不用把所有动作缩成无名图标。窄格滑条不够精细时仍可用±1或换帧面板，不降低帧精度。图片拖动、页面纵向滚动与滑条横向操作分别接管，不能在整格滥用touch-action:none锁住页面。

## 5. 复用和开源选择

- 采用现有原生range：本项目精确编辑器已用它，浏览器处理基本语义；新增的是有界预览与提交合同，不需要引入新UI库。[MDN range](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/range)、[Pointer capture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture)说明取值与拖出区域持续接收事件。来源已读，未冒充项目实测。
- 对照阅读[Radix Slider实际源码](https://github.com/radix-ui/primitives/blob/main/packages/react/slider/src/slider.tsx)：区分onValueChange与onValueCommit、手势前值比较、步长及键盘提交。借鉴职责分离，不复制整个实现；本项目只有Radix Context Menu，新增Slider包会增加接入/样式成本，本单不安装。开源源码只证明模式可用，不证明本页滑动性能。
- 保留现有dnd-kit/core6.3.1、sortable10.0.0，拖拽listeners只挂图片激活button；滑条是兄弟控件，不共用传感器入口。原图decode后替换及PhotoSwipe参考沿原单§20，实际继续使用本项目MultiviewFrameImage。
- 不选“每格挂隐藏video并逐帧seek”：多解码器和重复原片读取放大资源竞争；不选“每个onChange取PNG/存作品”；不升整条图集到高清。新增复杂worker/WebCodecs体系不是本次所需。
