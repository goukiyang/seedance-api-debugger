# 参考素材分辨率提交前拦截

## 1. 大白话目标复述

用户现在看到的“参考素材分辨率太低”已经是正确解释，但出现得太晚：素材已经进入生成提交，Provider 拒绝后才提示。目标是把问题提前到提交前发现，尤其是视频素材要在上传时写入宽高；生成页看到低分辨率素材就提示并禁止提交，后端 `/api/tasks/create` 再做兜底，避免其他入口绕过。

  - 检查对象：`src/lib/http/file-upload.ts`、`src/lib/assets/direct-upload.ts`、`src/lib/assets/site-upload.ts`、`src/lib/assets/storage.ts`、上传相关 API route。
  - 完成标准：图片和视频上传后都能把 `width/height` 写入 `Asset`；旧请求头兼容，新请求头用媒体宽高语义。

## 3. 验收/审查内容

这些审查项需要创建独立子 agent 做只读审查；审查 agent 不改文件、不提交、不补实现，只判断是否达标、证据是否充分、风险是否遗漏，并输出“通过 / 不通过、证据、缺口、风险、下一步”。

- [x] R1. 独立只读审查
  - 检查对象：本任务涉及代码、smoke 脚本、`npm run lint`、`npx tsc --noEmit`、`git diff --check` 输出。
  - 通过标准：低分辨率素材不会再进入 Provider 创建；上传链路不会丢视频宽高；没有修改点数、Provider 业务提交和数据库结构；已说明不能自动修复低分辨率视频的边界。
  - 证据来源：代码 diff、命令输出、必要时数据库字段/静态源码检查。
