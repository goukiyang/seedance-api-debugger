## 目标与范围

2026-10-01 用户反馈：昨天保存的“通用上下文”文案消失。随后确认：它应是一份对现有全部模板和以后新建模板同时生效的设置；模板原有的上下文要合并保留。用户授权恢复找回的原文，但要求本线程找到根因后只写工单、不自行实施，并把工单发送给“外部接入”线程。

完成标准：恢复原文；生成时实时组合“当前通用上下文 + 当前模板自己的上下文”，两者均保留、不重复复制到每个模板字段；以后创建或应用模板也自动遵循；避免页面初始化/切换分组时意外清空通用文案；旧任务快照不回写。其他图片/视频/积分业务不在范围内。

- 2026-10-01 已额外制作恢复前全库备份 `/data/video-api-debugger/srv-backups/image-studio-context-recovery-20261001/pre-restore.db`，`PRAGMA quick_check=ok`，其中此设置仍为空（revision 21）。备份含生产数据，只在服务器受限环境使用，不外传。尚未恢复原文。
- `src/app/image-studio/studio.tsx` 的首个可见模板组件持有全局草稿，初值为空；模板列表按分组切换会改变首组件。`loadSettings()` 异步读取，而 `dirty` 与 700ms 自动保存可能在读回前用空草稿调用 `saveSettings()`。`src/app/api/image-studio/settings/route.ts` 接受空 `context`，`src/lib/image-studio/settings.ts` 只做 revision 冲突检查、没有历史版本。因此存在可覆盖非空文案的确定代码路径；本次线上写入的具体浏览器动作/请求体无法从现有应用审计证明，不能冒称已锁定操作者。
- `src/lib/image-studio/tasks.ts` 的普通生成路径已把通用设置与模块上下文拼接；但复现历史任务分支改用旧任务快照的 `globalContext`，覆盖当前通用设置，导致此路径不遵循“当前通用上下文对所有模板生效”。模板库应用时模板上下文会进入模块字段，原模板文本不应迁移或覆盖。
- 当前无相关图片、视频或设计附件；本工单所需关键资料是上述数据库备份与源码入口。不要把整库备份上传 Git 或消息线程。
- 方案参考：[React 官方 `useEffect` 文档](https://react.dev/reference/react/useEffect) 的异步读取竞态清理方式；这里复用现有组件和 API 即可，不引入新组件库。该文档说明通用处理方式，不是本次线上请求的取证。
