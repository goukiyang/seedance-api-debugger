## 1. 目标与来源

用户原话：每次生成，模板上下文自动产生一段5位数字和字母组合的代码；改变标点也要变化，文字一样则不变。用户继续询问适合本项目的方案及不妨碍交互的显示位置，最后要求“工单”。

用户明确的核心要求是内容不变码不变，内容变化码变化。以下为本轮讨论整理的推荐实施方案：原文指纹加持久化五位短码，入口旁、上下文弹窗内及结果参数行显示。写工单不表示已实现或已获得本次生产写入、发布授权。

首批按图片模板的“模块上下文”编写；复用同一图片工作台组件的旧入口保持一致。通用上下文、补充提示词、固定图说明、视频模板及全站上下文版本管理不自行扩展。仅模块上下文相同，不代表最终生成提示词或全部生成配置相同，界面必须命名为“模块上下文版本”，不能冒称“完整生成版本”。若后续要求同时跟踪通用上下文，应另行明确编码对象，不能静默改变本码含义。

## 2. 编码规则

1. 输入为模块上下文原文，完整保留文字、标点、空格、换行和大小写；不trim、不替换中文标点、不做Unicode归一化或其他“清洗”。这段代码标识用户原文，不标识Provider最终拼接或清理后的提示词。
2. SHA-256完整指纹用于查找内容版本；相同原文稳定复用同一码，包括刷新、重开、多次生成、另存模板、历史恢复及改回旧文字。任务编号、用户每次点击的时间、模型、质量、比例和生成次数不得混入内容指纹。
3. 新原文分配5位码，建议使用大写A-Z与数字0-9，且每个码同时至少含一个字母和一个数字。A7K2M等仅为展示示意，不是已经计算的真实码。
4. 短码必须经过服务端持久化唯一占位；被其他原文占用则重新分配。仅截取哈希前5位不能满足要求。指纹查重和短码占位须在同一事务中处理，并发请求不能为同一原文分配不同码，或把同一码分配给不同原文。有限码空间耗尽或超过有限重试预算时给出明确错误，不无限循环、不覆盖旧映射。
5. 相同原文复用属于编码规则，不是新的上下文访问权限。映射保留在服务端，不新增匿名查询、按码读取私有原文或全站搜索接口；沿用现有模板/任务可见范围与上下文保密规则。
6. 空字符串是有效且可区分的原文版本；缺失快照不是空字符串，不能把缺失内容生成空文本码后冒称“已恢复”。
7. 五位码只是便于识别的版本标签，不是任务唯一ID、加密内容、密码或权限凭证；不写进上下文正文，不追加到发往Provider的提示词，也不自动保存/提交/生图或扣费。

- 常驻可见，不依赖悬停才能发现；不放封面角标、不遮图、不抢占点赞、收藏、查看和生成主操作。

- 短码支持点击和键盘复制，悬停/聚焦提示“模块上下文版本，点击复制”；附近短暂显示“已复制”，失败就地提示可重试，不弹确认或系统弹窗。复制事件不得冒泡成打开上下文、恢复历史设置或查看图片，禁止嵌套button。
- 上下文按钮仍只打开原设置弹窗；修改仍遵守原保存规则。编辑码旁标“未保存”，实际保存成功才移除该状态；码已算出不代表文字已保存或配置已生效。
- 正常打字只更新当前草稿的版本显示，不滚动、不抢焦点、不插入内容。建议短暂防抖，中文输入法组词完成后再请求；异步响应按请求序号核对，不把较早响应贴到较新的原文上，不为每个中间键盘事件新增数据库记录。
- 读取/编码失败不显示旧码冒充新内容，保留输入并提供就地重试；不得因为前端预览码未返回而新增无理由的生成拦截，仍以服务端最终快照确定该次版本。

## 4. 生成、历史与保存的对应关系

1. 生成提交由服务端在既有权限验证、实际原上下文选择完成后，针对该次有效的moduleContext计算/复用短码；前端提交的码仅供校对，不能当作权威。历史复现应使用原snapshot.moduleContext，不能使用当前模块值。
2. 将模块上下文版本码和编码规则版本保存进既有任务snapshot_json，任务列表返回允许展示的短码。版本码不计入现有“提交请求身份”或“计费”规则，不改变相同requestId的查询/重试语义。
3. 生成结果展示生成当时码，之后编辑模块、保存新上下文或改变通用上下文，都不能改写旧任务的码。点击历史封面恢复原模块上下文后，当前显示相应的原码，不新增确认弹窗、不自动生成。
4. 另存模板、快捷套用、恢复默认、浏览器临时草稿恢复以及重新打开弹窗都使用同一编码函数与内容映射，不维护第二套随机编号。
5. 新任务读取时优先展示已保存的码；旧任务仅在原模块上下文快照完整且有权限时，由服务端按原文惰性解析/登记。缺失快照显示“未记录”；不把当前内容当历史，不批量回写生产任务或虚构旧码。
6. 权限受限的共享模板只展示现有权限允许的版本标签，不因为显示码返回被隐藏的上下文、参考图说明或完整指纹；设置入口和原文复制权限保持原样。
