## 2. 推荐产品流程

沿用`/tools/character-lab`，不另造应用：原图 -> 面部候选 -> 选择主面部 -> 独立视图制作 -> 成品预览/保存导出。视图制作和预览在同一页面连续进行，不增加必须来回切换的独立页面。

### 2.1 面部变化强度

- 将“面部差异N%”改成“面部变化强度0–100”，低/中/高同一套服务端分档供前端显示。不声称是测量的相似度或图像编辑器的确定性变形。
- 推荐含义为候选之间的变化幅度；年龄感、角色气质、摄影角度、光线、服装和标志性配饰保持，避免发型/表情/体重变化冒面部变化。
- 低强度：围绕同一基准，仅变化1–2项局部比例，不强制长/方/圆脸跨骨相；0表示尽量贴近基准，不承诺完全相同像素。中强度扩大选定特征范围；高强度才允许明显不同骨相和身份方向。
- 有选中主面部时，可明确“以当前主面部继续探索”，由当前主面部作为冻结参考锚点；初次只有原设计图则以原角色特征为基准，不偷偷增加一次收费基准生成。保留4/9候选单张拼图，暂不顺手改成4/9次收费。
- 管理员规则与系统强度约束不得互相抵消。新规则版本去掉默认强制全局大差异/固定骨相表，已保存自定义规则不自动覆盖；预览发现冲突时展示实际有效规则供管理员显式修订。旧plan的prompt/configRevision与已生成图片原样保留。
- 拖动只改下一次生成参数，不自动收费；新生成受理后显示对应冻结强度，保留旧图并明确当前预览来自哪次生成，不让旧图和新滑杆值造成错觉。

### 2.2 四项独立制作

| 视图 | 独立输入与目标 | 操作 |
|---|---|---|
| 正面头部 | 选定主面部 + 原角色；纯正面、平视、中性表情 | 单独生成/重新生成/放大/选用 |
| 侧面头部 | 同一主身份；严格90度侧面，不是45度或三分之二侧脸 | 同上；默认固定一个侧向，重做时保持同向 |
| 纯正面全身 | 同一主面部 + 原角色服装/身体；身体与面部朝正前，完整头顶鞋底 | 独立按钮，不捆绑头部或背面任务 |
| 纯背面全身 | 同一角色服装/体型/发型；身体和头部朝正后，不回头、不露侧脸 | 独立按钮，不要求先生成其它视图 |

“纯正面/纯背面”按现有成品的全身正背理解；不是新增转台视频或精确3D重建。姿态约束写入各自专用prompt，输出仍须人工检查，不能只凭prompt声称角度合格。需要修正时只重新生成该项，不自动重做另三项。

默认分别操作；可提供明确的“生成所选视图”快捷命令，但每个子任务独立请求号、报价和结算，开始前显示本次几张与合计费用，不能沿旧“一张四格”的价格暗中提交四次。身份/素材/管理员规则与生成配置冻结在同一制作版本；改变主面部或原图建立新版本，不偷偷混入旧身份结果。

### 2.3 成品预览逐项上屏

- 保留现有四格版式：上排正/侧头部，下排纯正/背全身；格子位置和尺寸固定，不按完成顺序重排。任一合法成品ready即显示该项，其余格分别显示尚未生成、排队、处理中、待核对或失败。
- 单项完成即可查看、下载、选用和保存单张；不因另一项失败隐藏已完成图片，不把裁出来的旧格冒新独立生成。
- 选择每项满意版本后本地/服务端拼装预览，拼装不调用生成接口、不收费。全部四项选齐才称“完整成品”；缺项仍可导出已完成N张或保存明确标记的草稿，不拿空白格冒完整交付。
- 等待同一子项重做时保留已选旧版，显示新任务真实状态；新结果ready后由用户选用再替换，失败/未知不清旧图。关闭刷新恢复原子任务和选择，不自动重发；停止仅影响未受理任务。

### 页面与交互

1. **选头像。** 左侧保留原图和来源，主画布显示当前批次。四宫格、九宫格和变化强度放在同一生成设置。结果区分别显示本次请求的档位、格数和状态，以及当前仍在展示的旧批次。生成失败时留旧图并直接写清“本次九宫格生成失败，正在查看上一批四宫格”。组内仍可放大、选择、查看历史。
2. **微调头像。** 选中一格后在选中方案旁出现“微调这张脸”。同页弹出该格大图、修改描述和“生成四个方案”，保留同一个人的年龄感、骨相、发型和辨识点，只在指定细节上给四种变体。以已选格的合法裁图作为参考。生成前显示本次报价；新一批就绪后与原选中图对照，显式“设为正脸”才替换，原图和早先批次仍可回看。每一轮记住父图与本轮描述，下一轮从用户选用的版本出发。
3. **做头像与全身。** 成品区固定四格，上排正脸、侧脸，下排全身正面、全身背面。正脸直接用选定原像素，无额外正脸生成。侧脸独立生成，锁正脸作为身份依据，固定 90° 同向侧视，保持鼻唇轮廓、下颌、发型、年龄感和标志性配饰。点击侧脸可打开同款微调，仍锁正脸，当前侧脸只作为局部编辑参考；从四个侧脸候选中明确选用才替换右上格。若重新确定正脸，旧侧脸保存在历史并标待确认，需核对或重做。全身正背两项可并行，都只用原始角色图作图像输入，保留身体比例、轮廓、服装层次、材质、配色和配件，分别严格正对/背对并完整露出头顶与鞋。全身格各自完成即显示，等待另一项时可继续比较；更新头像无需重做全身。换原图时，新旧结果按来源隔离。原图缺少全身设计时，在下半区提示可更换为包含全身的原图；基于有限参考生成的结果仍由用户对照确认。
4. **确认后交付。** 右侧先显示当前选用版本，四格齐全时提供“合并保存”和“复制合成图”。两键使用相同的合成 PNG 和布局，复制不额外创建作品，合并保存记录当前四格选择和永久合成图。保留单格查看、下载和旧整图/ZIP入口。小屏按原图、候选或预览、操作的阅读顺序排列，主操作保持可达。

### 规则、执行和费用

- 人脸探索使用可解释的“小幅 / 中等 / 明显”三级约束，前后端共享分档。小幅只改变一两处指定比例，拿掉跨骨相和不同真人硬指令；中档扩大可变范围，高档才拉开身份或骨相。微调走独立规则，文本只描述想改的局部。管理员按设置打开弹窗，能按需看本阶段的自动构图、身份/参考规则与本次实际生效提示词；只编辑管理员有权修改的字段。已保存自定义规则里若存在强制换脸等冲突，提示管理员核对，沿原版本显式发布。实际任务固定计划及修订，旧请求和已保存规则不自动改写。
- 首轮四、九宫格沿单张报价起步。优先把已证的原异步失败定位到现有上游日志或原回执，并区分执行失败、返回缺图与布局不合规。拼图模型仍可能画错数量，不用九次坐标裁切冒九个有效人脸。需要保证可选格数时，设计成独立候选输出后本地排成宫格。只有清楚展示实际次数与合计并由用户显式发起才执行，旧单张失败不自动转成多次扣费。首轮四、九与细调是否需要这个模式，按真实模型样本和费用定稿。
- 复用既有图片任务、渠道与报价结算。每项计划记录用途、来源引用和素材版本、修订、原始任务号、实际提示词和参数。候选生成、头像微调、侧脸、侧脸微调、全身正/背分别使用明确的服务端输入规则。使用现有 owner、workspace 与来源校验。现有 prepareLab 以整个工作区阻止新提交；新独立制作需要把在途保护收窄到同一输出槽或候选批次。新流程允许不同格并行，同一槽的未知原请求仍只回查原号；旧请求沿旧口径处理。完成结果按任务和输入修订落历史，显式选用时用工作区修订及来源核对替换目标格，其他格和旧输入的迟到结果不能覆盖当前选用。
- 保留 v1 的 faces/result 及原整图，新增带版本的生成记录和成品选用引用，不补跑历史。成品按四个已选引用、布局版本和原件权限做确定性拼接，复用 Sharp。沿原 2:3 画布，上排约 42%、下排约 58%，等宽列，等比例放入格子并留安全边距，保全身原比例和头脚。服务端保护合并保存的幂等与 CAS，换图只改变新成品版本。复制与保存均不创建生成任务，失败保留已选引用及可重试入口。

当前图的“提示词”查看的是该生成记录冻结的实际内容/引用/参数，仍守原权限；输入框是下一次生成的个人要求。切历史自动带回该批对应补充，当前未发草稿另保，切回可接着写；不得把新输入写回历史提示词，也不把另一个部位的文字借来填空。浏览不自动替换模型、原图或整套参数；显式沿用全部设置仍保原入口语义。

### 17.4 依赖关系和最短正常路径

- 正脸：原图用于探索；微调以当前选定正脸为底图，身份与外观要求按本部位处理。
- 侧脸：选定正脸锁身份；微调同时使用当前侧脸。没有选定正脸时仅该区说明缺什么，并可直接回当前正脸候选，不阻止做身体。
- 正背面：原图决定头身比、身材、服装、配饰/材质与细节；局部微调另外使用当前正背组作为编辑底图，不能由头像推身体；仍成对生成和采用。
- 换正脸只使旧侧脸需要同步，旧图保留对照/历史，不清空、不自动重发、不连带重做身体。在侧脸区显示“按当前正脸同步”，实际按钮仍在补充下。未同步的组合可以继续编辑、保存工作草稿；新完整成品采用仍需满足既有身份匹配条件，原完整成品可找回，已有合法单图可用。
- 换原图保留旧原图全部历史与已受理任务，新的生成绑定新来源；旧任务迟到不得接管当前部位/输入。

首次进入：添加原图后直接在四格空版式编辑。正脸、正背面可从原图各自制作，不强迫先完成一个阶段；选定正脸后制作侧脸，齐全后在同页保存合成/复制/下载。明确选择和现有必要费用确认仍保留，取消无意义页面跳转；不承诺一次点击可跳过真实身份选择。

已有角色修改侧脸：进入即看到当前成品 → 点侧脸 → 写如“鼻梁收一点、下颌保持” → 生成本次4/9候选 → 对比并用一张 → 只替换侧脸。整个过程同页，正脸和身体保持采用状态。改身体只操作当前正背组；改脸造成的侧脸依赖就近说明。

### 17.5 状态、局部恢复与小屏

空工作区只突出添加原图；有原图无结果时三部位分别显示可执行动作及真实缺项。重新生成期间保留旧图/整张成品，仅目标区显示排队/生成/可选结果；可继续看图、编辑别处。是否可同时受理多个部位沿现有部位门/费用/原请求规则，不为视觉并排擅自承诺新的并发。

失败仅作用于本次局部请求，保输入/旧图/有效部分，提供原失败原因及合法下一步；提交未知只查原号，不能自动补发。回页/刷新恢复角色、编辑部位、采用版本及独立草稿，后台结果耐久可找回但不自动选用。生成、采用和成品保存各按真实状态反馈，不用全页loading盖住其他结果。

小屏保同一工作台：成品在前，选中部位的编辑面板就近展开，候选在主区比较；原图/左下历史移为可识别的素材/批次区域，不把桌面三栏整体缩小，不保留顶部阶段导航。尚无原型/浏览器实测，具体断点与触控布局待设计产物验证。

### 17.6 架构判断、实施边界及验收依据（均待实施）
