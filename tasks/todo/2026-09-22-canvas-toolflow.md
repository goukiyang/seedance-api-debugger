# 画布工具流基础能力

## 工单信息

- 日期：2026-09-22
- 项目：video-api-debugger
- 目标页面：现有画布工具页面
- 目标：在现有画布中搭建、保存和执行由多个图片生成模板组成的工具流
- 优先级：P1
- 当前状态：已完成（待审核）

## 用户目标

用户可以在画布中把多个图片生成模板组合成一条可重复执行的工具流，支持模板按顺序执行，也支持一张输入图片同时运行多个模板，全部完成后由用户筛选结果，再继续后续模板，最终将中间结果和最终结果保存到资产库。

## 已确认方案

复用现有画布作为工具流编辑器，不新建独立的工作流编辑页面：

现有画布 -> 工具流定义与版本快照 -> 工具流编排器 -> 现有图片生成任务队列 -> 图片生成 API -> 资产库

- 画布负责节点、连线、配置、保存、运行状态和结果选择。
- 后端编排器负责依赖判断、串行、并行、等待确认、重试和恢复。
- 第一阶段复用现有图片生成任务队列，不引入 n8n、ComfyUI、Temporal 或新的 Redis 基础设施。
- 后续并发量和流程复杂度达到阈值后，再评估 BullMQ Flows；官方支持父子任务、并行子任务、等待依赖完成和读取子任务结果：https://docs.bullmq.io/guide/flows/。
- 现有画布若基于 React Flow，继续复用 @xyflow/react，通过自定义节点实现工具流；官方核心库为 MIT 授权：https://reactflow.dev/。

## 节点类型

第一阶段实现：

1. 输入节点：上传图片、选择资产库图片、接收上游输出。
2. 模板节点：绑定现有图片生成模板并设置生成参数。
3. 结果筛选节点：等待用户单选或多选结果。
4. 人工确认节点：等待用户确认后继续。
5. 输出节点：写入资产库并标记最终产出。

暂不实现循环节点、自动条件识别、AI 自动编排、多层嵌套工具流和多人实时协作编辑。

## 模板节点配置

- 执行模式：自动执行、等待确认、跳过。
- 输入来源：当前输入、上一步结果、用户选择结果、资产库资产。
- 生成模型、质量、比例、生成张数。
- 模板上下文和本次描述补充。
- 失败重试次数。
- 是否将全部结果传给下游，或只传用户筛选结果。

## 并行执行

输入图片
  ├── 模板 A
  ├── 模板 B
  ├── 模板 C
  └── 模板 D
          ↓
      等待全部完成
          ↓
       结果筛选
          ↓
       后续模板

一个输入节点连接多个模板节点时，后端自动识别为并行分支。每个分支独立记录状态，单个分支失败不覆盖其他分支结果。

## 状态、积分和资产规则

工具流状态：

草稿 / 已保存 / 排队中 / 执行中 / 等待筛选 / 等待确认 / 部分成功 / 执行成功 / 执行失败 / 已暂停 / 已取消

- 节点状态必须独立显示，不能只显示工具流总状态。
- 失败状态要说明失败节点、原因、积分状态、可否重试和恢复位置。
- 执行前显示预计生成张数和预计积分。
- 已完成节点不重复扣费；取消时释放未执行节点的冻结积分。
- 每一步生成结果自动进入资产库，记录工具流名称、版本、节点、模板、输入资产和执行批次。
- 最终输出增加“最终产出”标记。

## 权限

- 管理员工具流可以共享给其他用户。
- 创作者工具流默认只有本人可见。
- 用户只能使用自己有权限访问的模板和资产。
- 运行时跨用户引用管理员共享资产时，必须通过现有资产复制/授权规则处理，不能绕过 owner 校验。

## 盘点结果（2026-09-22）

### 现有可复用入口

- 页面入口：`src/app/tools/ultimate-canvas/page.tsx`，负责登录/外部账号拦截，并以 iframe 加载 `public/tools/ultimate-canvas/index.html`。
- 画布核心：`public/tools/ultimate-canvas/canvas-engine.js` 的 `CanvasEngine`，当前持有节点、连线、视口、框选、拖拽和删除能力；`serialize()` 输出 `version / viewport / selectedNodeId / nodes / connections`，`restore()` 可完整恢复。
- 当前节点：已存在 `text`、`script`、`image`、`video`、`audio`、`director`、`video-compose` 等节点类型，图片/视频节点已有生成参数和生成状态展示逻辑。
- 保存入口：`src/app/api/tools/ultimate-canvas/document/route.ts` 的 GET/POST；前端 `app.js` 通过 `canvasSaveCoordinator` 防止旧上下文覆盖新上下文，并将 `schema: ultimate_canvas.v1`、项目/视频卡/分支上下文和画布快照写入 `CanvasDocument.document_json`。
- 恢复入口：`app.js` 的 `loadCanvasDocument()`，按项目读取服务端文档，校验项目归属，恢复视频卡/分支上下文，再调用 `engine.restore()` 和节点状态恢复逻辑。
- 运行入口：现有 `public/tools/ultimate-canvas/generation-api.js`、`generation-task-coordinator.js`、`generation-node-workflow.js` 与 `app.js`；文本/脚本走 `/api/tools/ultimate-canvas/generate`，图片复用 `/api/assets/generate`，视频复用 `/api/tasks/create`，现有任务状态继续由服务端接口和轮询负责。
- 资产入口：`upload/route.ts` 支持图片、视频、音频上传并将素材关联到当前项目/视频卡/画布节点；画布也能从当前项目素材库和历史记录创建节点。

### 第一阶段边界

- 不替换 `CanvasEngine`，不引入 React Flow；当前工程实际不是 React Flow 实现，todo 中的 React Flow 仅保留为后续评估项。
- 不新增第二套图片任务队列；工具流模板节点应复用现有图片生成接口和任务/资产归档链路。
- `CanvasDocument` 目前只保存“当前画布文档”，没有工具流定义、版本快照、运行记录和节点运行记录；第 2 至第 4 项需要新增独立的数据边界，不能把运行状态混入 `document_json`。
- 当前保存对象包含视频卡/分支上下文，工具流运行必须额外保存不可变流程快照，避免用户编辑画布后污染正在运行的流程。
- 当前权限复用 `assertInternalOnly`、项目访问权限和画布 owner/admin 判断；工具流共享权限需在独立接口中复用这些校验，不能仅依赖前端隐藏按钮。

### 直接影响后续实施的风险

- 当前 `CanvasEngine` 的连线结构只有 `from/to`，没有端口类型；工具流第 3 项需要增加兼容校验所需的端口元数据，同时兼容旧文档的无端口连线。
- 当前 `document_json` 有 2MB 上限，运行快照不能把大图二进制或完整资产内容写入画布，应只保存模板配置、资产 ID 和任务引用。
- 当前图片节点已有实际生成参数和结果恢复逻辑，可作为模板节点的配置来源；必须把“模板配置快照”和“节点当前编辑态”分开保存。

## 验收场景

1. 创建 A -> B -> C 线性工具流并成功运行。
2. 上传一张图片，同时执行四个模板。
3. 四个模板部分失败时，保留成功结果并可单独重试失败节点。
4. 四个模板完成后进入筛选节点，选择结果继续执行最终模板。
5. 节点设置为“等待确认”时，流程暂停且不提前执行后续节点。
6. 修改画布后，旧运行仍使用原版本快照。
7. 取消流程后，未执行节点积分释放，已完成结果保留。
8. 刷新页面、重新登录后，工具流定义和运行状态可恢复。
9. 普通用户不能读取或修改管理员专属配置和无权资产。
10. 旧图片生成页、模板页、资产库和现有画布功能回归通过。

## 风险与边界

- 不把浏览器画布状态当作任务真实状态，真实状态以服务端运行记录为准。
- 不在第一阶段引入第二套任务队列，避免积分、重试和任务状态分裂。
- 并发数量必须受上游图片 API 限流和账户成本限制。
- 流程定义、模板配置和运行快照必须分开保存。
- 用户筛选结果属于运行时数据，不回写覆盖原模板。
- 发布前必须验证数据库结构、服务端 worker、公网页面和真实登录态操作。

## 用户体验重整（2026-09-23）

用户反馈原工具流更像工程调试面板，普通用户需要理解节点、资产 ID 和连线才能开始。保留现有后端编排、积分和权限边界，在同一入口增加默认步骤模式：

1. 默认按“选择素材 → 选择生图模板 → 输出到资产库”完成任务；高级画布仅作为需要分支、筛选和人工确认时的入口。
2. 素材从当前项目资产库直接多选，支持上传图片和 `Ctrl/Cmd + V` 粘贴图片，不要求用户手填资产 ID。
3. 生图模板按现有分组展示，支持搜索、封面、模型、比例和张数摘要；可添加多个模板步骤、上下调整、删除，并自动映射为原有工具流节点。
4. 保存仍写入原工具流 API 和图快照；开始生成仍走原有运行记录、任务队列、积分冻结/释放和资产归档，不新增第二套执行链路。
5. 高级模式保留原节点设置、工作流选择、共享范围和输入资产 ID，用于兼容复杂流程和旧使用方式。

### 本轮验收标准

- 打开工具流后默认进入步骤模式，用户可以不理解节点概念完成素材选择、模板选择、保存和执行。
- 选择的模板与素材能回写到可保存的工具流图，刷新后仍能恢复模板步骤。
- 粘贴/上传图片使用真实 multipart 请求，不被 JSON 请求头破坏。
- 高级画布可切换，原有运行、暂停、确认、重试和共享范围控件仍可用。

### 用户操作链路

1. 系统的“无线画布”入口打开画布工作台，先选项目，再显示该项目下自己有权访问的画布；提供最近使用与继续上次画布。已有带 document_id 深链接直接打开原画布，不强制回列表。
2. 工作台复用系统项目权限和项目管理入口，不新建平行项目体系。项目列表可搜索；画布支持搜索、最近更新排序、分批加载，卡片显示有权缩略图、标题、更新时间、运行状态；姓名旁保留头像。
3. 项目内“新建画布”：默认“未命名画布”，可立即改名。先由服务器创建唯一 ID，再进入空白画布；重复点击不会创建多个。不因空画布没有节点而拒绝首次保存。
4. 编辑器保持满屏、无系统左栏；固定顶部显示“返回画布列表 / 项目 / 画布标题”，右侧为保存状态、保存图标、新建及更多菜单。标题点击编辑；保存有未同步内容时可用；新建与切换前先保存，失败则留在原画布。
5. 自动保存与手动保存共用同一个队列；Ctrl/Cmd+S 在编辑器内保存，不触发浏览器另存网页。状态区分未保存、保存中、已保存、离线待同步、保存失败可重试，不把本地暂存标成云端已保存。
6. 更多菜单提供重命名、复制画布、归档与恢复；第一期不做永久删除和跨项目移动。复制创建新 ID，只复制有权配置和素材引用，不复制运行中任务、不自动生成或扣分；默认不复制私人历史结果。
7. 切换画布不搬移内容；任务继续在服务器运行，结果回到提交时的项目、画布、节点和当前提交者的资产库。画布关闭/刷新不取消任务；归档不删除资产或任务，有任务运行时提示其继续执行。

### 积分展示与真实扣费

- 普通图片、模板、视频等付费生成节点统一在模型同行最右侧展示“本次 N 积分”；模型下拉每一项右侧展示在当前有效配置下的本次报价，悬浮/聚焦补充单价、张数或秒数、质量/分辨率和扣款账户。无已确认报价显示“待报价/未配置”，不显示 0 冒充免费。
- 示例排版：`[GPT Image 2.5 Sunburst v]                   本次 80 积分`，仅示例，不硬编码价格。纯素材/文本节点不伪造费用；完整流程显示本次会执行节点的合计，缓存复用、跳过节点不重复计费。
- 图片价格沿用通用上下文中的模型价格；视频沿用现有视频价格规则；Pro 不覆盖原配置，其他模型也不在前端写死20。质量/分辨率是否影响价格以现有权威规则为准，没有差价规则就不自行引入。未定配置拒绝生成并提供管理员设置入口。
- 增加统一报价服务，输入为项目、模型、有效规格、数量和执行范围；返回报价明细、账户范围、配置版本与过期信息。不接收前端传入金额作为扣款依据。变更参数时丢弃旧报价响应；加载或失败期间禁止按旧价提交。
- 提交时服务器重新校验参数、模型、模板共享权、资产权、余额、项目预算及报价版本。价格变更返回新报价让用户确认，不静默涨价；个人余额与公共项目预算分别沿用既有扣款口径，不得改扣另一个账户。
- 一个用户动作一个幂等请求 ID；冻结/任务创建原子完成，成功按实际交付结算、明确失败释放，部分成功逐张结算，余额同步更新。供应商结果不明进入待核实，不能自动重试导致重复上游费用。刷新、复制、保存不扣分。
- 普通图片链路改接可恢复任务服务，保留原有 Provider 配置、画布请求适配和资产归档返回契约；模板与视频现有链路保持，不重建第二套钱包/任务队列。先盘点所有 `/api/assets/generate` 调用方，再逐一兼容。

### 数据、保存与安全

- Document 保存节点、连线、节点配置、素材 ID、结果/任务引用、画布标题和归属；图片二进制、密钥、长期公开地址不入文档。单用户视角可跨设备恢复，协作时视角与选中态不覆盖别人的视角。延续2MB保护并给出可操作提示，不默默截断。
- 补充服务端 revision、snapshot schemaVersion 和有界历史恢复点；更新用条件写入，冲突返回409并允许另存副本/加载服务端版本，禁止静默覆盖。迁移为追加式，旧文档按兼容解析，原始 JSON 备份不改写丢弃。
- 本地草稿以用户+项目+document ID 隔离，只保存配置与资源引用，退出登录清理用户敏感缓存；断网恢复后比较版本再同步。上传未完成显示待上传，保存不能误称已可跨设备恢复。
- 文档加载、列表、封面、素材、报价、生成、复制、归档统一服务端授权；匿名/外部用户无权。默认列表只返回本人画布，项目共享画布只使用已明确授权记录，不从项目成员身份推导新增授权。旧协作画布逐项兼容，不在迁移时静默改权限。
- 新增 document 列表接口（游标、项目筛选、状态），详情/更新固定 document_id，创建使用幂等键；补齐复制/归档/恢复动作。bootstrap 不再用“最近一张”覆盖显式打开的 document；URL 固定 document_id，project_id 从服务端文档解析。
- 生成运行快照锁定 document_id、revision、node_id、project_id、提交者、模板版本和报价；编辑器后来切换项目/参数不改变运行。节点删掉后结果仍在任务和资产库可找回，回填不得误写同名新节点。
- 现有生成需要视频卡，第一期复用当前项目默认生成记录并在高级选项保留原视频卡选择，不再强迫纯生图用户理解视频卡；不能把一个项目的默认记录串到另一个项目。
