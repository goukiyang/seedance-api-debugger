# 模板系统 UX 重新规划设计

更新时间：2026-06-17  
依据：`AI 视频创作经验工作台需求文档 V1.pdf`、多角色 Agent 推演意见、当前线上源码 `/Volumes/Data/Projects/video-api-debugger-v12-full-todo`  
目标：从真实使用者角度重排模板系统，让普通用户、模板管理员、系统管理员、质量运营都能完成自己的闭环。

> 这份文档只做产品和 UX 重规划，不是代码实现清单。

## 1. 重新定位

当前系统不应该继续被设计成“模板后台 + 表单 + JSON 调试”。

新的定位应该是：

```text
团队级 AI 视频创作经验工作台
```

用户感受到的不是：

```text
我在配置模板字段
```

而是：

```text
我把创作经验封装成模板
我用模板快速生成视频
我能复盘为什么生成成这样
```

## 2. 当前难用的根因

多角色推演后，问题不是“功能少”，而是“功能摆放方式错了”。

### 2.1 工程概念暴露给了业务用户

这些概念不应该默认出现在主路径：

```text
Module Builder
PromptBlock
AgentRun
TemplateMemory
injectionMode
priority
prompt_required
context_only
validation_only
moduleType
reference_image_id
原始 JSON
Seedance Payload
Step input/output
```

它们可以存在，但只能放在：

```text
高级结构
开发视图
后台诊断
导出报告
```

### 2.2 页面按系统模块组织，不按用户任务组织

现在用户看到的是：

```text
模板库
模板生成
模块管理
AgentRun
API 设置
```

但用户真实任务是：

```text
普通用户：选模板 -> 输入需求 -> 生成视频
管理员：创建模板 -> 试生成 -> 发布
运营：发现跑偏 -> 复盘归因 -> 推动优化
系统管理员：配置 API -> 验证可用 -> 看失败诊断
```

页面应该按真实任务重新分层。

### 2.3 主路径被低频功能打断

普通用户进入模板生成页，应该只看到：

```text
模板摘要
视频需求输入框
生成 4 个方案
选择方案并提交
```

但现在会被项目、视频卡、图集、参考图、Prompt 编辑、参数栏、最近任务同时干扰。

### 2.4 管理员没有创建向导

管理员真正想做的是：

```text
用一句话创建模板草稿
审核
绑定素材
试生成
发布
```

现在实际路径是：

```text
先进入模板库
选已有模板
点编辑模板
进入大抽屉
在模块页里找 LLM 配置
再切规则 / 资产 / Prompt / Temporal
```

这不符合“从 0 创建模板”的心智。

### 2.5 保存、应用、发布状态混乱

用户会分不清：

```text
应用草稿
保存草稿
保存模块
保存模板
保存为新版本
发布模板
```

需要把状态变成人话：

```text
已生成草稿
已应用到当前模板，尚未保存
已保存为草稿
已通过试生成
已发布，普通用户可用
```

## 3. 使用者角色重新定义

| 角色 | 真实目标 | 不该看到什么 |
|---|---|---|
| 普通创作者 / 内容运营 | 选模板，写一句需求，生成视频 | 模块、规则 JSON、AgentRun、Memory、API 设置 |
| 模板管理员 / 创作负责人 | 把创作经验封装成模板并发布 | 原始 JSON、注入方式、底层 Step、手填 ID |
| 素材 / 品牌规则管理员 | 管理角色图、Logo、风格图和使用规则 | Provider Payload、AgentRun Step |
| 团队负责人 / 发布审核者 | 判断模板是否能给团队用 | 底层字段、调试日志 |
| 质量运营 / 复盘人员 | 找到跑偏原因并推动优化 | 无关账务字段、原始日志堆叠 |
| 系统管理员 / API 运维 | 配置 LLM、权限和诊断 | 普通生成操作细节 |

## 4. 新信息架构

系统主入口收敛成 4 条线。

```text
1. 模板库
   给普通用户找模板、用模板

2. 模板生成
   给普通用户输入需求、选方案、提交生成

3. 模板工作台
   给管理员创建、试生成、发布、优化模板

4. 后台诊断
   给系统管理员和质量运营看 API、AgentRun、Memory、失败原因
```

### 4.1 普通用户导航

普通用户只需要：

```text
模板库
模板生成
我的生成
项目
```

普通用户不显示：

```text
模块管理
AgentRun
Memory
API 设置
模板底层 JSON
```

### 4.2 管理员导航

管理员显示：

```text
模板工作台
模板库预览
质量复盘
模块库
后台诊断
API 设置
用户与权限
```

### 4.3 后台入口分层

不要把所有后台入口平铺。

推荐分组：

```text
创作管理
├─ 模板工作台
├─ 模块库
├─ 素材规则库
└─ 质量复盘

系统诊断
├─ API 设置
├─ AgentRun
├─ OperationLog
└─ Memory
```

## 5. 普通用户体验重设计

### 5.1 页面：模板库 `/templates`

核心任务：

```text
让用户快速判断哪个模板适合自己，并进入生成。
```

第一眼应该看到：

```text
模板封面
模板名称
一句话用途
适用场景
使用模板按钮
```

普通用户模板卡片只保留：

```text
封面
名称
适合做什么
推荐时长 / 比例
使用模板
```

隐藏：

```text
规则数量
模块结构
提示词模块数量
素材完整度细节
更新时间
底层版本号
```

这些信息可以放进“更多信息”。

管理员额外看到：

```text
编辑
复制
停用
查看质量记录
```

但不能干扰普通用户主视图。

### 5.2 页面：模板生成 `/template-generate`

核心任务：

```text
用户输入一句需求，系统生成 A/B/C/D 方案。
```

首屏主舞台：

```text
当前模板摘要
你想生成什么视频？
[输入框]
[生成 4 个方案]
```

模块顺序：

```text
1. 当前模板摘要
2. 视频需求输入
3. 生成方案按钮
4. A/B/C/D 方案卡片
5. 最终 Prompt 预览，默认折叠
6. 提交生成按钮
7. 最近任务，放下方
```

默认隐藏：

```text
项目选择
视频卡选择
参考图详情
模板规则详情
Prompt 编辑
分辨率 / 时长 / 比例高级参数
```

默认策略：

```text
项目：自动使用个人默认项目
视频卡：自动创建或使用最近可生成视频卡
Prompt：自动生成，用户可展开编辑
参数：按模板默认值锁定，用户可展开调整
```

状态提示：

```text
未选模板：请先选择模板
模板缺素材：该模板缺少素材，可能影响效果
生成方案中：正在根据模板生成 4 个方向
已生成方案：请选择一个方案继续
Prompt 已编辑：你已修改 AI 生成版本
任务已提交：可继续生成下一条
```

验收标准：

```text
用户从模板库进入后，3 步内可以提交生成：
1. 输入需求
2. 选择方案
3. 提交生成
```

## 6. 模板管理员体验重设计

### 6.1 页面：模板工作台 `/admin/templates`

替代“在模板库里打开编辑抽屉”的主路径。

核心任务：

```text
创建、维护、试生成、发布模板。
```

建议布局：

```text
左侧：模板列表
中间：模板预览 / 试生成结果
右侧：模板状态与下一步操作
```

左侧列表显示：

```text
模板名称
状态：草稿 / 待试生成 / 可发布 / 已发布 / 已停用
素材完整度
最近质量问题
更新时间
```

中间主舞台显示：

```text
模板用途
绑定素材预览
规则摘要
试生成结果
A/B/C/D 方案预览
```

右侧操作面板显示：

```text
下一步建议
缺失项
发布检查
主要按钮
```

每个状态只有一个主按钮：

| 状态 | 主按钮 |
|---|---|
| 空状态 | 用 LLM 新建模板 |
| 草稿 | 继续完善 |
| 素材缺失 | 绑定素材 |
| 规则缺失 | 审核规则 |
| 未试生成 | 试生成 |
| 可发布 | 发布模板 |
| 已发布 | 优化新版本 |

### 6.2 页面：LLM 新建模板向导 `/admin/templates/new`

核心任务：

```text
管理员用自然语言创建模板草稿。
```

步骤：

```text
1. 描述模板目标
2. LLM 追问缺失信息
3. 生成模板草稿
4. 审核结构化结果
5. 绑定素材
6. 审核规则
7. 试生成
8. 发布
```

每一步只做一件事。

#### 第一步：描述模板目标

页面显示：

```text
这个模板适合生成什么视频？
[大输入框]
[生成模板草稿]
```

辅助输入：

```text
场景：品牌宣传 / 产品展示 / IP 角色 / 活动推广
目标时长
画面比例
是否需要 Logo
是否需要固定角色
```

不要显示：

```text
moduleType
PromptBlock
rules JSON
```

#### 第二步：LLM 追问

如果信息不够，LLM 不直接生成。

页面显示：

```text
还需要补充：
1. 是否有固定角色参考图？
2. Logo 是否必须出现？
3. 视频希望几段？
```

管理员补完后再生成。

#### 第三步：草稿审核

不要显示大段 JSON。

应该显示人话预览：

```text
模板名称
一句话用途
适用场景
默认比例 / 时长
素材需求
角色规则
Logo 规则
风格规则
镜头建议
禁止项
Prompt 格式
缺失信息
```

提供按钮：

```text
接受草稿
重新生成
局部修改
查看高级结构
```

#### 第四步：绑定素材

素材绑定不应该是 URL 表单。

应该是：

```text
角色图：选择 / 上传
Logo 图：选择 / 上传
风格图：选择 / 上传
产品图：选择 / 上传
反例图：选择 / 上传
```

每张素材绑定规则：

```text
这张图用来做什么？
必须进入最终 Prompt / 仅作为上下文 / 只用于校验
必须保持什么？
禁止改变什么？
```

#### 第五步：审核规则

规则展示成业务语言：

```text
必须遵守
禁止出现
建议参考
仅作为上下文
```

每条规则显示：

```text
规则内容
影响范围：角色 / Logo / 风格 / 镜头 / 素材
是否进入最终 Prompt
风险等级
```

隐藏：

```text
priority
injectionMode
target
sort_order
```

#### 第六步：试生成

管理员输入测试需求：

```text
用这个模板试做一个新品发布视频
```

系统生成：

```text
A/B/C/D 方案
最终 Prompt
生成任务
```

试生成结果用于发布检查。

#### 第七步：发布

发布前检查清单：

```text
LLM API 已配置并测试通过
模板名称和用途已填写
至少绑定一张素材，或明确不需要素材
至少有一组 MUST / FORBID 规则
Prompt 格式模块存在
已完成一次试生成
试生成结果已确认可用
敏感信息检查通过
```

通过后才能点击：

```text
发布模板
```

发布后提示：

```text
模板已发布，普通用户现在可以使用。
```

## 7. Module Builder 体验重设计

Module Builder 不应该混在复杂表单里。

推荐做成专门抽屉：

```text
新增模块 / Module Builder
```

主路径：

```text
描述模块
↓
LLM 生成草稿
↓
人话预览
↓
应用到当前模板 / 保存到模块库
```

页面显示：

```text
模块类型：自动判断 / 角色 / Logo / 风格 / 镜头 / 规则 / 素材规则 / Temporal / 提示词格式
你想创建什么模块？
[输入框]
[生成模块]
```

生成结果不要默认显示 JSON。

应该显示：

```text
模块名称
模块类型
这个模块会影响什么
会写进最终 Prompt 的内容
只作为上下文的内容
只用于校验的内容
必须遵守
禁止出现
建议参考
缺失信息
```

高级结构折叠：

```text
查看 JSON
查看 injectionMode
查看 priority
查看 target
```

状态提示：

```text
已生成模块草稿，尚未应用
已应用到当前模板，尚未保存模板
已保存到模块库
已保存模板，用户生成时会生效
```

## 8. 素材带规则体验重设计

素材不是一张图 URL，而是“可复用的创作约束”。

推荐新增：

```text
素材规则库
```

素材卡片显示：

```text
图片预览
素材名称
素材类型：角色 / Logo / 风格 / 产品 / 反例
默认用途
绑定规则数量
被哪些模板使用
```

素材详情显示：

```text
基本信息
默认规则
模板内覆盖规则
使用历史
最近质量问题
```

绑定规则分三类：

```text
必须写进最终 Prompt
只给 LLM 做上下文
只用于生成后校验
```

模板内使用素材时：

```text
继承默认规则
允许本模板覆盖
覆盖内容明确标注
```

## 9. 发布审核体验重设计

发布不是状态下拉。

应该有发布工作流：

```text
草稿
↓
待试生成
↓
待审核
↓
已发布
↓
已停用
```

发布审核页显示：

```text
模板摘要
素材完整度
规则完整度
试生成结果
风险提醒
变更摘要
发布影响范围
```

发布者要能判断：

```text
这个模板适合谁用？
会不会破坏品牌？
有没有试生成过？
普通用户是否能看懂？
失败后是否能复盘？
```

需要补的能力：

```text
复制模板
停用模板
发布新版本
回滚版本
查看发布历史
查看使用次数
查看质量问题数量
```

## 10. 质量复盘体验重设计

当前 AgentRun 是技术日志。

需要新增：

```text
质量复盘工作台
```

入口：

```text
/admin/outputs
任务详情
用户反馈
AgentRun 详情
```

页面布局：

```text
左侧：视频结果 / 首帧 / 参考素材对比
中间：用户需求 / Agent Prompt / 最终 Prompt / 模板规则
右侧：归因与下一步建议
```

复盘字段：

```text
问题类型：角色变形 / Logo 丢失 / 风格跑偏 / 镜头不对 / 分段断裂 / Prompt 格式错误 / Provider 随机失败
归因对象：模板 / 模块 / 规则 / 素材 / Prompt / Provider / 用户输入
证据：截图、任务、Prompt 差异、命中规则
建议动作：修改规则 / 替换素材 / 修改 Prompt 格式 / 调整模板
处理状态：待处理 / 已转优化 / 已修复 / 已回归验证
```

Memory 展示改成三层：

```text
当前任务 Memory
模板历史 Memory
可行动 Memory
```

每条 Memory 应显示：

```text
问题类型
归因对象
关联模板版本
证据链接
运营判断
建议动作
处理状态
回归结果
```

验收标准：

```text
运营 30 秒内找到模板、方案、AgentRun
2 分钟内看清用户需求、Prompt、素材、规则
5 分钟内完成结构化归因
归因能写入 Memory
能生成模板管理员优化待办
改完模板后能重跑历史问题验证
```

## 11. 系统管理员体验重设计

API 设置页不能只有保存。

必须有：

```text
当前状态
测试连接
最后测试时间
测试模型
测试耗时
最近错误
去诊断
```

Musk API 设置显示：

```text
启用状态
Base URL，默认 https://api.muskapis.com/
Model，默认 gpt-5.4
API Key 是否已配置
测试连接
保存
清除 Key
```

测试连接要验证：

```text
HTTP 是否成功
模型是否可用
是否能返回 JSON
耗时
错误码
```

LLM 未配置时，所有 LLM 入口都要显示：

```text
LLM 未配置，无法生成模块或模板。
[去 API 设置]
```

并禁用：

```text
生成模板草稿
生成模块草稿
生成规则草稿
```

后台诊断总览显示：

```text
LLM API 状态
最近 20 次 LLM 失败
最近 20 次权限拒绝
最近 OperationLog
最近 AgentRun failed
一键跳转 trace
```

## 13. 统一状态语言

所有页面统一使用这些状态文案。

| 状态 | 用户看到 |
|---|---|

## 15. MVP 重排

第一阶段不追求完整系统，先跑通体验闭环。

### P0：立即改善主路径

## 16. 页面验收标准

### 普通用户

```text
进入模板库

输入一句需求
看到 A/B/C/D 方案

```

### 模板管理员

```text
点击 + 用 LLM 新建模板
输入模板目标
LLM 追问或生成草稿
审核人话结构
绑定素材
审核规则

普通用户可见
```

### 质量运营

```text
看到结果、素材、规则、Prompt 差异
完成归因
写入 Memory

重跑历史问题验证
```

### 系统管理员

```text
配置 Musk API

LLM 入口根据配置状态启用或禁用

敏感信息不泄露
```

## 17. 最终设计原则

后续所有模板相关页面都按这几条判断：

1. 普通用户只表达目标，不理解系统结构。
2. 管理员只审核经验，不手填底层 JSON。
3. AI 负责结构化，但不能绕过人工确认。
4. 系统负责提示状态，不能让用户猜是否生效。
5. 复盘要能推动优化，不只是展示日志。
6. 一页只保留一个主任务，一个主按钮。
7. 高频动作可见，低频和高级功能折叠。
8. 发布前必须试生成，发布后必须可追溯。

一句话收敛：

```text
把工程后台改成三个工作台：
普通用户生成工作台，
管理员模板工作台，
运营质量复盘工作台。
```
