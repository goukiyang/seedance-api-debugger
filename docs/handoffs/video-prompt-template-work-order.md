## 1. 已确认目标

用户原话：“应该是跟图片一样，给一段固定上下文，和一段通用上下文，然后再输入框里输入我们要的内容，再生成出文案。”

复用图片模板的页面结构和使用习惯。在现有模板工作台的视频大类内，使用“通用上下文 + 当前模板固定上下文 + 本次输入”，调用网站现有后台文字模型，生成可编辑、可复制的视频文案或提示词。

主流程只需：选择模板 → 填写本次需求 → 生成文案 → 编辑或复制。带到视频生成是可选的后续动作，不自动提交视频任务。

## 2. 范围与保护边界

- 保留图片/视频两个大类，不增加第三个大类，不另建工作台或后台。
- 保留现有分组、模块和左侧独立上下滚动，不重构为另一套导航；现有直接生成视频能力不得删除或隐藏到不可达。
- 不强制增加用途筛选、复杂动态表单、分镜编辑器、工作流编排或素材必填步骤。此前讨论的复杂输入方案不属于本单要求。
- 沿用账号、权限、后台文字接口、任务记录和费用体系，不在前端放 API Key，不允许前端指定任意服务地址。
- 本单不接入新模型、不修改视频 Provider、不付费生成、不改历史生产数据、不自动执行数据库迁移。
- 仅讨论/工单交付不升级网站版本、不部署；未来实现交付按项目规则自动发布，功能由用户手动验收。

## 3. 页面与保存规则

| 区域 | 设计要求 | 保存与权限 |
| --- | --- | --- |
| 顶部通用上下文 | 沿用图片页面的设置入口，作用于视频提示词模板，不影响图片模板上下文 | 先核对图片现有作用域及权限；显式保存，不随本次输入自动覆盖。若图片规则本身不明确，先确认是个人还是共享，不能自行扩大作用范围 |
| 模块上下文 | 当前模板的一段固定规则，沿用“模块上下文”入口 | 显式保存；不能影响其他模板。普通使用者不得读取不属于其权限的模板内部规则 |
| 本次输入 | 一个主要输入框，填写这次需求；提示文字使用业务语言 | 按账号和模块自动保存个人草稿，不覆盖两层上下文。刷新恢复行为复用该页面当前已确认的草稿规则，不能另建冲突行为 |
| 生成文案 | 唯一主要操作，调用现有后台文字模型 | 提交前由程序保存/快照本次输入，不要求先手动保存设置或另存模板 |
| 文案结果 | 右侧展示可编辑文本；提供复制、重新生成、历史入口 | 结果与手改草稿分开保留；新结果不能覆盖用户正在修改的文本 |
| 带到视频生成 | 作为结果区次要操作 | 只填入最终选中的文本和兼容参数，不提交视频任务、不冻结视频点数 |

“复制上下文”继续仅向管理员开放；“复制文案”面向有权使用该结果的用户。二者不能混用权限。

首期默认不要求上传素材。若保留参考素材入口，不能声称模型理解了图片：现有 worker 只收到素材类型/槽位文字描述，真实读图不是本单默认范围。

## 4. 后台处理与保密

1. 服务端校验登录、模板使用权限、草稿归属、文字服务可用状态及必要输入。
2. 服务端读取通用上下文和模块上下文，形成此次调用的版本快照，再组合用户输入；用户输入是待处理内容，不能获得模板管理权限或改变系统规则。
3. 优先保留现有文字任务、请求防重和 worker 处理链路，只补必要字段及设置入口，不另起重复任务系统。
4. 通用上下文定义共同规则，模块上下文定义本模板要求，本次输入提供具体需求；模块不能越过通用安全边界，用户内容不作为泄露内部规则的指令执行。
5. 前端只获得授权后的文案、用户输入、业务状态和必要结果标识。内部上下文原文不能出现在普通用户的模板详情、运行快照、历史、handoff、错误或公开共享接口里。
6. 不能仅靠隐藏按钮保护上下文；也不能靠一句“不要泄露”保证大模型输出安全。需设计最小上下文、结构化输出和异常泄露处理；密钥/凭据绝不能放进上下文。无法保证绝对不被模型复述的剩余风险须如实回执。
7. 重新生成创建新记录，不覆盖历史；超时或断网先查询原任务，避免重复请求和费用。刷新后可以找回处理中/失败/成功记录。
8. 文案费用遵循现有后台真实规则，提交前显示免费或实际计费口径；不得自行发明点数价格。视频费用在视频生成环节另行确认。
9. 文案结果作为纯文本显示，不能把模型输出作为 HTML 执行。
