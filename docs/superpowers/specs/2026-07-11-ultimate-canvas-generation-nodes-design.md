# 无线画布图片与视频节点原位增强设计

## 目标

在现有无线画布中直接补完整图片节点和视频节点。节点从输入、参考素材、生成设置、真实提交、状态反馈到结果复用形成闭环，不新增页面，不嵌入普通生成页，也不增加第三方调用。

生产请求只使用 sd2 同源接口：

- 图片：`POST /api/assets/generate`
- 视频：`POST /api/tasks/create`
- 视频状态：`GET /api/video/status/:taskId?refresh=true`
- 提示词辅助：`POST /api/tools/ultimate-canvas/generate`
- 素材：`GET /api/assets/library` 和现有上传接口

## 当前问题

现有代码已经有基础请求适配器，但节点交互仍是半静态原型：

- 图片和视频节点上的多枚工具按钮没有事件处理。
- 视频页签只切换视觉状态，部分节点不会保存新的生成模式。
- 比例、尺寸、时长、分辨率、声音等规格不可编辑，页面仍显示固定假数据。
- 参考图只在提交时隐式扫描连线，节点内看不到数量、顺序、首帧或尾帧归属。
- 图片结果虽能写回节点，但缺少清晰的资产动作和快速建立下游视频节点的入口。
- 视频结果有基础轮询，但提交参数、错误恢复、规格恢复和结果动作没有统一闭环。

## 方案选择

采用节点原位增强方案。继续复用 `CanvasGenerationAPI` 和现有节点/连线模型，将纯请求构造与状态归一化收敛到可测试的浏览器模块。

不采用以下方案：

- 不把普通生成页组件嵌入节点，避免引入 React 页面状态和画布状态两套所有权。
- 不只接两个生成按钮，因为这会继续保留可见但无效的假控件。

## 图片节点

### 模式

- 文生图：`text_to_image_reference`
- 图生图：`image_variant`，至少需要一张有效参考图。
- 高清修复：`image_variant`，至少需要一张有效参考图，并补充高清修复意图。
- 首帧草图：`first_frame_draft`
- 尾帧草图：`last_frame_draft`

### 设置

节点内可编辑比例、尺寸和输出数量。尺寸与输出数量上限来自 `bootstrap.capabilities.image`，不允许填写任意模型或 provider 参数。

### 参考素材

直接连入图片节点的已上传/已生成图片作为参考图。节点显示参考图缩略图和数量。点击“选择参考”打开现有素材面板；从素材面板选择后创建图片素材节点并自动连接到目标节点。

提交只传已入库的 `reference_image_id`。没有入库 ID 的本地预览不伪装成可用参考图，并给出明确提示。

### 结果

成功后保存 `asset_id`、`reference_image_id`、`workspace_asset_id`、原图和缩略图 URL。节点显示预览、打开原图、下载、再次生成和“生成视频”。“生成视频”创建一个相连的视频节点，参考图通过连线自然进入视频提交。

## 视频节点

### 模式

- 文生视频：`all_in_one_reference`，允许无参考图。
- 全部参考：`all_in_one_reference`，使用所有有效连入图片。
- 图生视频：`all_in_one_reference`，至少一张有效图片。
- 首尾帧：`first_last_frame`，第一张图片为首帧，第二张为尾帧，至少需要首帧。
- 图片参考：`all_in_one_reference`，至少一张有效图片。

模式切换同时写入节点数据和画布文档，恢复后保持一致。

### 设置

节点内可编辑比例、时长、分辨率、生成声音、返回尾帧和水印。默认值来自当前视频卡和普通生成页规则。模型名只读自 bootstrap，不开放任意模型或 provider 配置。

固定的假点数数字改成“后台计费”；真实冻结点数在任务创建返回后显示。

### 提示词工具

- “优化提示词”调用无线画布文本接口，将结果写回当前视频提示词，用户仍可编辑后提交。
- “运镜”打开内联预设菜单，选择后把结构化运镜文本加入提示词并保存到 `cameraPresets`。
- “选择参考”打开现有素材面板并将选中图片节点自动连入当前视频节点。
- “设置”打开节点内规格面板。

不保留没有后端或明确本地行为的假按钮。

### 提交与轮询

提交 payload 对齐普通生成页，包含项目、视频卡、方向、模式、规格、参考图、幂等键和 `source_metadata`。页面用户点击继续走现有付费保护和点数规则，不增加绕过 header。

创建成功后保存任务 ID、冻结点数和提交快照；串行轮询到 `succeeded`、`failed` 或 `cancelled`。刷新页面后，非终态任务继续轮询。

成功节点显示缩略图、播放、下载、任务详情和再次生成；失败节点保留提示词、设置和参考图，并允许重新提交。

## 状态与错误

节点状态统一为：

- `idle`
- `validating`
- `submitting`
- `submitted`
- `running`
- `succeeded`
- `failed`
- `cancelled`

验证错误不发送请求。接口错误展示后端 `message/error`，保留输入和素材。视频轮询短暂失败自动退避，达到上限后暂停而不把任务误判为失败。

## 保存恢复

画布文档保存以下节点数据：

- 模式和生成设置
- 提示词和运镜预设
- 当前项目、视频卡、方向快照
- 图片资产标识与 URL
- 视频任务标识、状态、预览和下载 URL
- 最近一次请求和错误

恢复时重新渲染节点控件、参考图摘要和结果；仅非终态视频任务恢复轮询。

## 测试

1. 纯契约烟测先失败，再实现请求构造、模式映射、参考图规则和结果归一化。
2. 预览 API 烟测覆盖图片生成结果写回、视频创建及多次轮询到终态。
3. 浏览器实际点击图片和视频节点，检查模式、设置、参考素材、提交状态和结果动作。
4. 运行语法检查、TypeScript、既有无线画布烟测、lint 和生产构建。

## 边界

- 不修改 `.env`、后台 API 设置、点数核心逻辑、provider 密钥配置或数据库 schema。
- 不直接调用第三方 API。
- 不把普通账号改成 admin。
- 本地自动测试只使用内存 mock，不声称完成线上真实生成，也不消耗真实点数。
