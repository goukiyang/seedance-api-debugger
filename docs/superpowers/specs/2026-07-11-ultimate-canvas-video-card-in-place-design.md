# 无线画布视频卡原位增强设计

## 1. 目标

在现有无线画布页面内完整接入 sd2 已有的视频卡工作流。用户继续使用当前项目/视频卡选择器、提示词窗口、生成节点和结果节点，不跳转到另一套工作台，也不复制普通生成页形成第二套业务流程。

生产环境中的保存、上传、文本生成、图片生成、视频生成、状态轮询及视频卡管理全部调用同源 `/api/...` 接口。部署到 `https://sd2.youdoodesign.com` 后，由普通登录账号的会话 Cookie、项目角色和视频卡权限决定可见内容及允许操作。

## 2. 强制约束

- 不读取或修改 `.env`。
- 不修改后台 API 设置、provider 密钥配置、点数核心规则或数据库 schema。
- 不使用管理员身份绕过普通账号权限。
- 不直接调用第三方 API Key；模型调用只经过 sd2 后端现有接口。
- 不新增独立视频卡页面、固定侧栏、底部工作台或第二套生成提交流程。
- 保留本机 `4399` Mock 预览作为无点数 UI 验收工具，但 Mock 不作为真实接口验证证据。
- 不增加视频卡硬删除能力；继续遵循归档、废弃、封板、重开审批及审计规则。

## 3. 交互结构

### 3.1 顶部项目与视频卡上下文

保留现有项目和视频卡触发器。视频卡触发器继续显示当前卡标题、状态及 `比例 · 时长 · 分辨率`，并追加当前方向名称。

现有视频卡菜单采用两级原位内容：

1. 列表级负责搜索、选择、新建、查看状态及进入当前卡管理。
2. 当前卡管理级在同一个浮层内显示“信息、方向、记录、操作”四个区段，使用返回按钮回到列表，不打开新页面。

首次打开菜单或完成卡片级修改后，列表级通过 `GET /api/projects/:id/video-cards` 刷新当前项目的完整可见列表；搜索在已返回列表内即时执行，不受 bootstrap 首屏数量限制。

菜单根据后端权限显示操作：

- 可查看用户：卡片信息、方向和任务记录只读。
- `can_generate` 用户：可以选择活跃方向并从现有节点提交生成。
- `can_manage` 用户：可以编辑、封板、管理方向、标记版本、迁移任务、拆分、合并、归档或废弃。
- 封板、归档、合并、废弃状态保持只读，并展示后端返回的阻止原因。

### 3.2 卡片信息

“信息”区段展示并在允许时编辑：

- 标题、目标、平台；
- 比例、时长、目标分辨率；
- 预算点数和预算币种；
- owner、状态、生成次数、成功/失败/运行数量；
- 已估算、已扣除、已返还点数和官方成本摘要；
- 当前最佳任务和最终任务。

保存调用 `PATCH /api/video-cards/:id`。比例已锁定、公共项目或已有最终版时，界面不尝试绕过规则，而是允许提交 `ratio_change` 审批申请。封板或归档卡需要继续生成时，允许提交 `video_card_reopen` 审批申请。

### 3.3 方向分支

“方向”区段调用现有分支接口，支持：

- 创建方向；
- 选择本次生成方向；
- 设为主方向；
- 关闭方向；
- 合并到主方向；
- 升格为独立视频卡。

选中的 `video_branch_id` 同时写入画布文档上下文和视频生成节点数据。关闭、合并或升格当前方向后，重新读取分支并回退到主方向；没有主方向时回退为无方向生成。

### 3.4 提示词窗口和真实提交

继续使用当前节点的完整提示词窗口。在视频节点的现有参数区显示只读的项目、视频卡和交付规格，并提供方向选择器。

视频请求继续提交到 bootstrap 返回的 `capabilities.video.endpoint`，默认是 `POST /api/tasks/create`，请求至少包含：

- `project_id`；
- `video_card_id`；
- 可选 `video_branch_id`；
- `canvas_document_id`、`canvas_node_id`、`tab_id`；
- prompt、生成模式、比例、时长、分辨率；
- 参考资产 ID 或回退 URL；
- 幂等键、最终提示词快照和画布来源元数据。

文本和图片继续走各自的 sd2 同源 capability endpoint。画布前端不出现 provider Key、后台配置名称或第三方请求地址。

### 3.5 视频结果节点和版本管理

视频结果仍留在原视频节点内，不新建任务页面。节点根据真实任务状态显示 `submitted`、`running`、`succeeded`、`failed` 或 `cancelled`，并保留任务 ID、provider 任务 ID、播放地址和下载地址。

成功任务在节点现有动作区提供：

- 播放和下载；
- 标记候选版；
- 标记当前最佳；
- 标记最终版；
- 迁移到同项目另一视频卡，可同时选择目标方向；
- 调用现有重试接口，并继续沿用当前项目、视频卡和方向。

版本操作调用 `PATCH /api/video-cards/:id`；任务迁移调用 `PATCH /api/video-cards/:id/tasks`。操作成功后同时刷新节点数据、卡片详情和任务记录，不依赖乐观假状态。

### 3.6 生命周期、拆分和合并

“操作”区段复用当前确认弹窗并支持：

- 封板：`PATCH /api/video-cards/:id`，提交 `{ seal: true }`；
- 归档或废弃：`PATCH /api/video-cards/:id`，提交生命周期 `action`；
- 拆分：选择当前卡任务，调用 `POST /api/video-cards/:id/split`；
- 合并：选择同项目目标卡，调用 `POST /api/video-cards/:id/merge`；
- 比例变更和重开申请：调用 `POST /api/approvals`。

危险动作必须展示源卡、目标卡、任务数量及不可逆影响。后端返回 409 时保留用户选择和填写内容，展示业务冲突，不自动降级为其他动作。

## 4. 数据与接口

### 4.1 首屏数据

`GET /api/tools/ultimate-canvas/bootstrap` 继续提供普通账号、项目列表、视频卡列表、当前上下文、能力状态和基础权限。首屏不携带完整任务历史，避免增加画布启动负担。

### 4.2 懒加载数据

用户进入当前卡管理级时并发读取：

- `GET /api/video-cards/:id`：卡片详情、权限和摘要；
- `GET /api/video-cards/:id/branches`：方向及方向摘要；
- `GET /api/video-cards/:id/tasks`：可见任务、版本和成本字段。

数据按视频卡 ID 缓存在前端运行时。任何修改成功后只失效受影响视频卡缓存，并重新读取 bootstrap 保持列表状态一致。切换项目时清空卡片、方向和任务缓存，防止跨项目数据串用。

### 4.3 现有接口映射

| 能力 | 接口 |
| --- | --- |
| 视频卡列表/创建 | `GET/POST /api/projects/:id/video-cards` |
| 视频卡详情/编辑/版本/生命周期 | `GET/PATCH /api/video-cards/:id` |
| 方向读取/创建 | `GET/POST /api/video-cards/:id/branches` |
| 方向状态操作 | `PATCH /api/video-cards/:id/branches/:branchId` |
| 任务读取/迁移 | `GET/PATCH /api/video-cards/:id/tasks` |
| 拆分视频卡 | `POST /api/video-cards/:id/split` |
| 合并视频卡 | `POST /api/video-cards/:id/merge` |
| 比例变更/重开申请 | `POST /api/approvals` |
| 视频生成 | `POST /api/tasks/create` |
| 视频状态 | `GET /api/video/status/:taskId?refresh=true` |
| 视频重试 | `POST /api/video/retry/:taskId` |
| 播放/下载 | `GET /api/video/play/:taskId`、`GET /api/video/download/:taskId` |

本次不增加新的聚合 API。已有接口缺少无线画布所需的非敏感展示字段时，只扩充现有响应序列化，不改数据库和点数逻辑。

## 5. 保存与恢复

画布文档的 `context` 保存：

- `project_id`；
- `video_card_id`；
- `video_branch_id`；
- 文档 ID 和工作区键。

视频节点数据保存：

- 提交时的视频卡和方向 ID；
- task ID、provider task ID 和任务状态；
- 生成参数、最终提示词快照和参考素材；
- 播放、下载和缩略图信息；
- 当前版本角色和失败信息。

恢复时先验证项目与视频卡仍可见，再验证方向仍为活跃状态。未完成任务使用现有串行 `setTimeout` 轮询恢复；切换项目、视频卡或删除节点时停止旧轮询。旧保存或旧请求响应不能覆盖当前上下文。

## 6. 错误与权限体验

- `401`：提示重新登录，不伪装管理员，不清空画布输入。
- `403`：显示业务阻止原因并刷新权限；不暴露密钥或后台设置名称。
- `404`：标记卡片、方向或任务已不可用，并回退到当前项目的有效上下文。
- `409`：保留表单与选中任务，展示冲突及后端建议。
- `429/5xx/网络错误`：保留节点、提示词和素材，允许原位重试。
- 所有修改按钮在请求期间锁定，使用服务端响应作为最终状态。
- 切换上下文前先完成旧上下文保存；保存失败时阻止切换并提供手动重试。

## 7. 代码边界

- `public/tools/ultimate-canvas/app.js`：上下文协调、真实接口调用、节点与菜单事件接线。
- `public/tools/ultimate-canvas/video-card-workflow.js`：视频卡详情、方向、任务的纯状态归一化与请求 payload 构建，供浏览器和 smoke test 复用。
- `public/tools/ultimate-canvas/index.html`：按现有脚本顺序加载工作流模块，不改变页面入口。
- `public/tools/ultimate-canvas/styles.css`：扩展现有菜单、表单、任务行和移动端样式，不增加固定工作台布局。
- `src/app/api/tools/ultimate-canvas/bootstrap/route.ts`：仅补足现有响应中缺少的非敏感权限和展示字段。
- `scripts/smoke/ultimate-canvas-video-card-workflow-smoke.ts`：锁定接口路径、payload、权限、保存恢复和无第三方直连约束。
- `scripts/ultimate-canvas-preview-server.mjs`：补齐上述操作的内存 Mock，仅用于无点数本机 UI 验收。
- `docs/handoffs/ultimate-canvas-implementation-report.md`：记录文件、命令、真实调用和点数情况。

## 8. 验证标准

### 8.1 自动验证

- JavaScript 语法检查通过。
- TypeScript 类型检查通过。
- lint 和生产构建通过；既有无关警告单独记录。
- 原有三个无线画布 smoke test 通过。
- 新增视频卡工作流 smoke test 覆盖：
  - 方向 ID 进入生成请求和画布保存；
  - 普通账号权限决定操作可见性；
  - 编辑、封板、版本标记、方向操作、迁移、拆分、合并及审批使用正确的现有接口；
  - 任务状态恢复与串行轮询；
  - 不包含第三方地址、API Key、管理员绕过或敏感配置提示。

### 8.2 本机无点数验收

本机 Mock 验证完整 UI 状态和操作顺序，但明确标记为 Mock。桌面与移动视口检查菜单不溢出、文本不重叠、节点不位移。

### 8.3 生产真实验收

代码部署到 `https://sd2.youdoodesign.com` 后使用普通测试账号验证：

1. 登录、项目和视频卡可见范围；
2. 保存恢复、上传和方向恢复；
3. 文本、图片和视频真实提交；
4. 视频从提交轮询到终态；
5. 任务归属、版本标记和视频卡摘要；
6. 权限拒绝、失败返还和点数流水。

任何可能消耗点数的真实图片或视频生成必须由用户在页面手动触发，并在回执中记录是否消费及最终状态。

## 9. 完成定义

只有在现有画布内能够完成视频卡选择与管理、方向选择与管理、真实生成提交、任务轮询、版本标记、任务迁移、拆分合并、生命周期操作及保存恢复，且普通账号权限和 sd2 后端规则没有被绕过时，才视为功能完成。无法在本机证明的生产调用和点数行为必须在回执中明确列为待线上验证，不能用 Mock 结果替代。
