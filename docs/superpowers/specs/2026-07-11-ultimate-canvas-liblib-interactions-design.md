# Ultimate Canvas Liblib-Style Interaction Design

日期：2026-07-11

## 1. 目标

在不迁移现有画布引擎、不新建页面和不改变 sd2 生成接口的前提下，原位优化无线画布的图片与视频节点交互，使核心操作方式接近 Liblib：节点未选中时紧凑，选中后原位展开；模式与规格使用锚定弹层；引用素材直接从画布选择；无效模式即时禁用；生成结果和再次生成保留在同一节点。

费用估算排在本轮最低优先级，不得阻塞其余交互优化。

## 2. 已确认边界

- 保留 `CanvasEngine`，不迁移 React Flow。
- 保留当前 sd2 视觉语言，不逐像素复制 Liblib。
- 所有生成仍走 sd2 同源接口。
- 普通账号可用，不增加 admin 绕过。
- 不读取或修改 `.env`、后台 API 设置、provider 密钥、点数核心逻辑和数据库 schema。
- 不添加“标记、特效、角色库”等没有现成后端语义的假按钮。
- 不直接调用第三方模型 API。

## 3. 方案比较

### 方案 A：迁移 React Flow

将静态画布页面重写为 React 和 `@xyflow/react`。优点是直接获得成熟的节点、端口和连线状态管理；缺点是需要重写当前导演台、素材面板、项目/视频卡上下文和已有事件绑定，回归范围过大。

结论：不采用。

### 方案 B：保留引擎，复刻核心交互

在现有 `CanvasEngine` 上增加选中展开状态、统一弹层、画布引用选择模式、能力驱动的模式/规格和节点内结果状态。现有节点坐标、缩放、连线、保存格式和 sd2 接口继续复用。

结论：采用。它能获得主要交互收益，同时保持改动集中、可测试、可回退。

### 方案 C：只改 CSS 外观

仅调整尺寸、颜色和按钮布局。实现快，但无法解决引用选择、模式约束、结果复用、弹层和恢复体验。

结论：不采用。

## 4. 节点交互状态

### 4.1 未选中状态

- 节点只显示标题、媒体预览或生成状态摘要。
- 空图片节点显示“文字生成图片”“使用参考图”，空视频节点显示“首帧生成视频”“首尾帧生成视频”。点击快捷入口只选中节点、展开表单并切换模式，不直接提交生成。
- 端口始终可见，拖线、拖动节点和画布缩放不受影响。
- 节点尺寸稳定，动态状态文字不得改变连接器位置。

### 4.2 选中状态

- 同一时间最多一个节点展开。
- 选中节点提升层级，并将宽度扩展为约 620px；宽度受当前视口约束。
- 有结果的节点在上方保留结果预览，下方显示提示词和生成控件。
- 没有结果的节点直接显示提示词和生成控件。
- 切换节点不会丢失未提交的提示词、模式、规格或引用顺序；输入实时写回 `node.data`，继续使用现有防抖保存。
- 展开、收起、结果媒体加载和设置变化后必须重新计算连线路径。

### 4.3 连接稳定性

- 节点和 SVG 连线继续共享同一 `translate + scale`。
- `CanvasEngine` 为节点内容尺寸变化增加 `ResizeObserver`，统一调用 `_updateConnections()`。
- 连接器锚点仍通过世界坐标计算，不改用屏幕坐标。

## 5. 控件布局

### 5.1 图片节点

选中后的顺序为：

1. 结果预览或空状态。
2. 引用、模式和快捷处理工具。
3. 有序引用缩略图。
4. 提示词编辑区。
5. 模型名称、规格摘要、提交按钮。

图片生成成功后不再把节点替换成只读结果卡。用户可以在同一节点修改提示词、引用或规格后再次生成，也可以创建一个已连接的视频节点。

### 5.2 视频节点

选中后的顺序为：

1. 视频结果、任务进度或空状态。
2. 引用、提示词优化、运镜和高级设置入口。
3. 有序引用缩略图。
4. 提示词编辑区。
5. 模型名称、模式、规格摘要、任务按钮。

模型只有一个时显示为只读名称，不伪造模型下拉菜单。以后 bootstrap 返回多个可用模型时，同一控件可以升级为模型弹层。

## 6. 统一锚定弹层

模式、规格和运镜使用一个共享的锚定弹层控制器：

- 弹层挂到页面顶层，位置锚定触发按钮，并限制在视口内。
- 同一时间只允许一个弹层打开。
- 点击外部、按 Escape、选择菜单项或切换节点时关闭。
- 打开状态通过 `aria-expanded` 表达。
- 弹层打开和关闭都不提交生成，也不改变项目数据，只有选中具体值才写回节点。
- 节点移动、画布缩放或窗口尺寸变化时关闭弹层，避免浮层与节点错位。

### 6.1 模式弹层

- 图片模式和视频模式都收进单个模式按钮，不再横向铺满五个标签。
- 每个模式显示名称、输入要求和不可用原因。
- 不符合引用数量的模式保持可见但禁用。

### 6.2 规格弹层

- 图片集中显示比例、尺寸和数量。
- 视频集中显示比例、时长、分辨率、声音、尾帧和水印。
- 选项从 bootstrap 能力数组生成，不在模板里写死另一套取值。
- 摘要行实时更新，但只影响下一次提交，不改写已经完成的任务。

### 6.3 运镜弹层

- 保留当前已有运镜预设，不选择预设时不修改提示词。
- 提供搜索和“当前已选”状态。
- 选择预设后只维护一条结构化运镜描述，重复选择时替换旧运镜行，不重复堆叠。

## 7. 从画布选择引用

点击“引用”后进入临时选择模式：

- 原节点保持高亮，画布显示“从画布选择参考”“返回节点”“退出”状态条。
- 兼容的图片节点高亮；不兼容节点降权且不可选。
- 点击兼容节点后创建到目标节点的连接，并把引用追加到目标节点的有序引用列表。
- 点击同一素材不会重复添加。
- 每个引用缩略图提供单独移除按钮；移除时同步删除对应连接。
- Escape、退出按钮或删除目标节点会结束选择模式。
- 选择引用本身不触发生成。

全局素材库继续保留。用户从素材库把素材加入画布后，可以在引用选择模式中选中它；现有“为目标节点添加素材并自动连线”的路径继续兼容。

引用顺序以连接创建顺序为准并持久化。首尾帧模式中，第 1 张显示“首帧”，第 2 张显示“尾帧”；超出允许数量时停止继续选择并显示原因。

本轮只把已入库图片作为图片/视频生成引用。视频和音频节点继续存在，但在后端 provider 能力没有明确开放前不伪装成可用参考类型。

## 8. 能力驱动与模式约束

bootstrap 在不暴露后台配置的情况下返回前端可用能力：

- `modes`
- `ratios`
- `durations`
- `resolutions`
- `supports_audio`
- `supports_last_frame`
- `supports_watermark`
- `max_reference_images`
- 图片的 `size_options` 和 `max_outputs_per_request`

前端契约模块根据能力和当前引用数量计算每个模式的状态：

- 文生视频：不需要引用。
- 全部参考/图生视频/图片参考：至少 1 张图片。
- 首帧视频：恰好使用第 1 张图片。
- 首尾帧：至少 1 张，最多 2 张；第 2 张作为尾帧。
- 智能多帧：后端能力开放时至少 2 张；未开放时不显示。
- 图生图和高清修复：至少 1 张图片。

提交按钮在校验失败时禁用，并在节点状态区直接显示第一条缺失条件。不得等用户点击后才用弹窗告知基础输入错误。

## 9. 结果与任务体验

- 图片结果写回原节点并进入素材库，原节点继续可编辑和再次生成。
- 视频创建后立即显示任务 ID 和提交状态。
- 视频结果、播放、下载、重试和版本标记继续留在原节点。
- 生成中的节点允许查看设置，但提交按钮禁用，避免同节点重复创建任务。
- 付费重试继续保留明确确认，不改变点数规则。

## 10. 轮询与恢复

保留现有 sd2 单任务状态接口，但把多个独立定时器改为一个画布级轮询协调器：

- 协调器维护所有非终态任务及其节点 ID。
- 同一轮并发读取活跃任务，单个任务失败不阻断其他任务。
- 前台从 3 秒逐步放宽到 8 秒；页面隐藏时使用 15 秒。
- 连续错误采用指数退避并限制最大间隔。
- 页面恢复时从节点数据重新注册所有非终态任务。
- 节点删除、项目切换或任务终态时立即注销。
- 终态变化仍触发现有画布保存和素材刷新。

本轮不新增批量状态后端接口；协调器保留以后消费 batch endpoint 的接口边界。

## 11. 保存与恢复

- 继续使用 `/api/tools/ultimate-canvas/document` 保存完整文档，不引入数据库 schema 变化。
- 所有模式、规格、引用顺序、运镜、展开所需结果数据和任务状态写入 `node.data`。
- 不保存瞬时 UI：打开的弹层、引用选择模式和 hover 状态。
- 保存序列化时清除 `blob:` 和 `data:` 临时地址，避免刷新后恢复无效资源。
- 项目/视频卡切换继续先 flush 当前上下文，避免串写。

## 12. 错误处理

- 能力加载失败：节点仍可查看，提交禁用并显示“生成能力暂不可用”。
- 引用未入库：缩略图标记不可用，不计入模式要求。
- 保存失败：保留本地节点状态和现有重试入口，不清空用户输入。
- 任务轮询失败：节点显示自动重试状态；达到上限后提示刷新仍可恢复。
- 媒体加载失败：显示占位图，提示词、设置和再次生成仍可用。
- 弹层定位失败：关闭弹层，不移动节点。

## 13. 费用最低优先级

费用估算只在上述交互全部完成后处理：

- 视频可调用现有 `/api/tasks/estimate`。
- 费用只做展示，不修改冻结、扣除、退款或项目预算逻辑。
- 估算失败时显示“提交后由后台计算”，不得阻止生成。
- 图片没有稳定估算接口时继续显示后台计费，不新增固定点数。

## 14. 测试设计

### 14.1 纯契约测试

- 能力数组生成规格选项。
- 引用数量决定模式启用、禁用和原因。
- 首尾帧角色按顺序计算。
- 重复引用去重、单独移除和顺序持久化。
- 运镜预设替换旧运镜行。
- 轮询协调器注册、注销、终态和错误退避。

### 14.2 源码烟测

- 图片/视频模式使用弹层，不再使用固定横向标签。
- 引用选择模式、状态条、退出和兼容节点高亮存在。
- 选中展开、未选中收起和 `ResizeObserver` 存在。
- 提交禁用原因、同节点结果和再次生成操作存在。
- 无第三方 API URL、Key、admin 绕过和固定点数。

### 14.3 本地 API 闭环

- 保存并恢复模式、规格、引用顺序、结果和任务。
- 两个并发视频任务由同一协调器轮询到不同终态。
- 删除节点后不再轮询。
- 刷新后恢复非终态任务。

### 14.4 浏览器验收

1. 创建图片节点，未选中时紧凑，选中后展开。
2. 从画布选择引用，连接与缩略图同时出现。
3. 引用不足时图生图/首尾帧显示禁用原因。
4. 模式、规格和运镜弹层只打开一个，Escape 可关闭。
5. 图片生成后结果与表单保留在同一节点。
6. 从图片结果创建视频节点并自动连线。
7. 视频生成中刷新页面，任务继续恢复轮询。
8. 390px 视口无页面级横向滚动，弹层不越界。
9. 浏览器 console 无新增 error/warn。

## 15. 验收标准

- 图片和视频节点的主要操作方式与 Liblib 一致，但使用 sd2 现有能力和视觉。
- 所有可见按钮都可执行或明确禁用，不存在静态假交互。
- 设置和引用在提交前即可看到有效性反馈。
- 生成结果不会把节点变成不可再次编辑的静态卡片。
- 多任务恢复和轮询不会重复请求或互相阻塞。
- 原有导演台、项目、视频卡、上传、保存恢复和普通账号权限不回归。
- 费用估算未完成也不影响本轮主要验收。
