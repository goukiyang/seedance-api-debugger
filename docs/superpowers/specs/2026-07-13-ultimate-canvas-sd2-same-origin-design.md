# Ultimate Canvas SD2 同源后端接入设计

日期：2026-07-13
目标分支：`teammate/ultimate-canvas-complete`
目标站点：`https://sd2.youdoodesign.com`

## 1. 背景与目标

无线画布生产代码已经使用相对 `/api/...` 路径调用 SD2 业务接口，但本地 `4399` 页面由 `scripts/ultimate-canvas-preview-server.mjs` 提供 Mock 数据，因此本地预览不能证明线上登录、项目权限、点数和真实模型链路可用。

本次目标是把现有画布原位部署到 SD2 同源环境，并确认普通登录账号可以完成以下闭环：

1. 读取项目、视频卡、点数和模型能力。
2. 保存与恢复画布文档。
3. 上传图片并写回资产、参考图和工作区标识。
4. 提交文本、图片和视频生成。
5. 将生成结果写回当前节点，并持续轮询视频任务到终态。
6. 刷新页面后恢复未完成视频任务和画布上下文。

本次不重建后端，不增加第三方 API Key，也不把普通用户绕成管理员。

## 2. 方案选择

采用 SD2 同源部署方案。画布继续请求相对接口，由浏览器自动携带 `sd2.youdoodesign.com` 的同源登录 Cookie。

不采用以下方案：

- 不让本地 `127.0.0.1` 直接跨域请求 SD2，因为登录 Cookie、CORS 和 SameSite 规则会让行为偏离生产环境。
- 不在前端保存 Cookie、Token、API Key 或自定义后端地址。
- 不开放全站反向代理或完整后台 CORS。

本地 Mock 服务器继续保留，仅作为无点数 UI 和交互回归工具，不作为真实后端验收环境。

## 3. 系统边界

### 3.1 前端画布

`public/tools/ultimate-canvas/app.js` 负责：

- 从 bootstrap 读取当前用户、项目、视频卡、点数和能力状态。
- 根据后端返回的 endpoint 配置生成适配器。
- 构造保存、上传、文本、图片和视频请求。
- 把成功结果归一化后写回节点。
- 注册视频任务轮询，并在刷新恢复时重新注册未终结任务。
- 在失败时保留提示词、规格和参考素材。

前端只能使用 bootstrap 返回的能力、模型和允许规格，不能传递 provider 密钥、自定义 `base_url` 或任意 provider 配置。

### 3.2 SD2 业务接口

生产部署继续复用以下同源接口：

| 能力 | 接口 |
| --- | --- |
| 启动上下文 | `GET /api/tools/ultimate-canvas/bootstrap` |
| 画布保存与恢复 | `GET/POST /api/tools/ultimate-canvas/document` |
| 文本生成 | `POST /api/tools/ultimate-canvas/generate` |
| 图片上传 | `POST /api/tools/ultimate-canvas/upload` |
| 图片生成 | `POST /api/assets/generate` |
| 视频生成 | `POST /api/tasks/create` |
| 视频状态 | `GET /api/video/status/:taskId?refresh=true` |
| 项目与视频卡 | 现有 `/api/projects/...` 与 `/api/video-cards/...` 接口 |

这些接口继续执行现有登录、项目成员、视频卡状态、点数冻结/扣除/返还和 provider 调用规则。画布不复制这些规则。

## 4. 数据流

### 4.1 页面启动

1. 用户以普通账号登录 SD2。
2. 浏览器打开 `/tools/ultimate-canvas`。
3. 页面通过 bootstrap 读取可见项目、可用视频卡、点数、最近画布文档和 `capabilities`。
4. 前端按后端返回的能力启用或禁用文本、图片和视频提交按钮。
5. 若存在未完成视频任务，恢复节点后重新启动状态轮询。

### 4.2 文本与图片生成

1. 用户在当前节点手动点击生成。
2. 前端捕获当前 `project_id`、`video_card_id`、画布文档、节点、提示词、规格和参考图。
3. 请求 SD2 同源接口。
4. 后端按普通生成页规则完成权限、能力和点数校验。
5. 成功后，前端只接受当前仍有效的请求结果，并把资产标识和预览地址写回节点。
6. 失败后保留用户输入和参考图，显示后端返回的可操作错误信息。

### 4.3 视频生成与轮询

1. 用户手动点击视频生成。
2. 前端提交项目、视频卡、节点来源、模式、规格和参考图标识。
3. 后端创建真实任务并返回任务标识。
4. 前端立即保存任务标识并启动状态轮询。
5. 轮询持续到 `succeeded`、`failed` 或 `cancelled`。
6. 成功时写回视频、缩略图和下载地址；失败时保留配置并提供重试入口。
7. 页面刷新后，从保存文档恢复任务标识并继续轮询。

## 5. 权限与安全

- 普通账号必须登录，但不要求 `admin`。
- 项目和视频卡的可见性、可生成状态与普通生成页一致。
- `sealed`、`archived`、`merged` 等不可生成视频卡继续由后端阻止提交。
- 前端不读取或输出 Cookie、Token、API Key、签名 URL 内部信息或数据库路径。
- 不修改 `.env`、后台 API 设置、provider 密钥配置、点数核心逻辑和数据库 schema。
- 自动化验证不得批量创建付费任务。
- 真实图片或视频生成只由用户在页面中明确点击触发，并按现有点数规则计费。

## 6. 错误处理

- `401`：提示登录失效，并保留当前画布输入。
- `403`：显示项目或视频卡权限原因，不提供管理员绕过。
- 能力禁用：使用 bootstrap 中的 `capabilities.*.message`，不引导普通用户进入后台设置。
- 点数不足：显示后端原始业务提示，不修改或绕过点数规则。
- 上传失败：保留本地选择状态，允许用户重试。
- 图片生成失败：保留提示词、参考图与规格。
- 视频创建失败：不进入伪轮询状态。
- 视频轮询暂时失败：采用现有退避策略继续尝试；达到终止条件后显示明确错误。
- 上下文切换期间返回旧请求：继续使用现有请求身份与上下文校验丢弃过期结果。

## 7. 部署与验收

### 7.1 静态与构建验证

- `git diff --check`
- `node --check public/tools/ultimate-canvas/app.js`
- `node --check public/tools/ultimate-canvas/canvas-engine.js`
- 全部 `ultimate-canvas-*-smoke.ts`
- `npx tsc --noEmit --pretty false`
- `npm run lint`
- `npm run build`

### 7.2 SD2 同源验收

使用普通测试账号在已部署分支或临时预览环境验证：

1. `/tools/ultimate-canvas` 不返回 `401/403`，且不需要管理员身份。
2. bootstrap 中项目、视频卡、点数与普通生成页一致。
3. 保存后刷新，节点、连接、视口、活动节点和任务状态可以恢复。
4. 上传图片后，节点与素材库使用真实资产标识。
5. 文本生成写回当前节点，旧请求不会覆盖新上下文。
6. 图片生成写回真实资产、参考图和工作区标识。
7. 视频生成创建真实任务，并轮询到后端终态。
8. 失败路径保留输入，点数行为沿用后端规则。
9. 页面控制台无新增错误，网络请求均指向 SD2 同源 `/api/...`。

自动验收只执行不产生付费任务的检查。真实图片和视频生成需要用户在测试账号中明确手动触发，并在回执中记录是否消耗点数。

## 8. 完成标准

- 当前画布无需更换 UI 或新建流程即可使用 SD2 真实业务接口。
- 普通账号完成文本、图片、视频三类生成闭环。
- 保存、上传、结果写回、轮询与刷新恢复可用。
- 所有模型调用只经过 SD2 后端。
- 本地 Mock 与线上真实环境职责清晰，不把 Mock 响应带入生产部署。
- 实施回执完整记录修改文件、验证命令、真实调用和点数消耗情况。
