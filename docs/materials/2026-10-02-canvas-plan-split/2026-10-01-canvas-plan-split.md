## 1. 推荐结论

采用“结构化生成优先、原文解析兜底、AI 仅辅助歧义识别”的双入口方案，统一输出可追溯的方案组，再接现有图片、视频生成与结果管理。

不更换现有画布引擎，不引入完整 Dify/LangExtract 服务，不新建第二套计费或生成队列。对现有任务能力做差距核对，不假定所有节点已经具备任务幂等、锁价、恢复等能力；缺项是批量生成开放前的阻塞条件，不用前端禁用按钮冒充可靠保障。

用户已明确目标：右键增加方案拆分；覆盖不同使用场景；上下游形成闭环。以下细节是推荐实施规格，不应表述为已经上线或逐项经过用户验收。

## 3. 用户路径

文本节点右键：编辑文本、拆分为独立方案…、复制文本、复制节点、删除节点。分组分隔；生成角色图/视频继续使用已有快捷创作入口，避免重复堆菜单。

点击拆分后展示轻量预览：识别的方案数量、每项标题及原文片段、共同要求、待确认内容。支持改标题、合并/拆开边界、调整次序、取消选中和更改归属。标明“保留原节点，不自动生成”。

明确结构直接给预览，不调用模型；歧义明显时提供“智能识别”，请求前按真实能力说明费用或费用未知状态，不把付费调用伪装成免费解析。失败保留原文及手动拆分入口。

确认后在原节点右侧空闲区域创建方案组，紧凑排列，避免覆盖已有节点；选中整个新组以便继续。组级入口为共同要求、批量生成、结果对比；分支可单独编辑与生成。不额外制造装饰性巨型容器或重复公共说明节点。

预览关闭只取消本次应用；存在手改时保护草稿。外部点击/Esc 只关闭顶层，恢复焦点。编辑文本时保留原生文字右键能力；非右键用户可从节点更多菜单访问同一操作。

## 4. 识别方案

### A. 本站新生成：结构先行

支持多方案的文本生成返回结构化结果：方案组类型、方案列表、共同要求及适用项、说明。文章视图由同一份结构渲染，不独立维护一份可能不一致的长文本。

模型输出先校验再保存；合法 JSON 不等于方案语义正确。缺字段、截断、混入非目标类型时不得当作可直接拆分的有效结构。保留普通文本兼容结果及可恢复错误，不进行无限模型重试。

用户自由编辑长文本后，原结构与文本版本不一致即标记需重新解析；不能继续拿旧结构拆新文章。仅重新展开未改内容时不再次请求模型。

### B. 粘贴及历史文本：保留证据

1. 为原始文本保存版本及稳定的段落标识，保留字符位置映射；展示所需的规范化不得破坏原文回溯。
2. 优先解析 Markdown 标题、列表、普通段落与编号；“方案一/二”等只作为候选证据，不能靠一个关键词或段落数量硬切。表格、引用和代码块不随意拆散。
3. 有歧义时，模型只给段落归属、分支类型及依赖建议，不改写正文、不创建节点、不触发下游工具。原文内的命令只作为待分析内容。
4. 服务端校验段落标识真实存在、范围有效、方案非空、顺序合理、覆盖情况和重复归属。更细粒度拆分由原文选择范围确定，不让模型自行计算中文字节位置。
5. 未归属内容进入待确认区。共同要求只能在有明确依据或用户确认时生效；无法判断不默认对所有分支应用。
6. 同一段确需供多方案使用时保留一次原文并建立多个引用，不以禁止重叠为由丢内容。用户取消的方案标为排除，不当作识别遗漏。

不使用模型自报的置信度百分比作为放行条件。可靠等级依据可检查事实：已有有效结构、标题边界明确、存在歧义或内容待归属。所有路径都允许用户预览修正。

## 5. 场景判定

| 内容 | 语义 | 处理 |
|---|---|---|
| 方案一至方案四 | 并列备选分支 | 首版直接支持 |
| 四个步骤、四项修改意见 | 一个方案的组成部分 | 不自动当四方案；提示调整 |
| 四个镜头、分场脚本 | 有顺序的镜头列表 | 后续专门类型，保留时序和角色依赖 |
| 角色、场景、道具清单 | 可复用实体 | 后续实体提取，允许跨段多处证据 |
| 一个方案要变出四种方向 | 新内容创作 | 独立“衍生方案”，不得冒充无损拆分 |
| 方案二沿用方案一角色 | 显式跨分支依赖 | 预览确认具体引用范围，不把另一方案全文并入 |
| 统一要求与单项例外并存 | 有作用范围的约束 | 显示共同要求及例外；冲突不静默覆盖 |

## 6. 最小数据契约

先复用现有画布文档存储，不预设新增数据库表。实施前核对文档大小限制、字段白名单、历史快照与复制行为。确需持久化迁移时单独说明。

| 对象 | 必要信息 |
|---|---|
| 原文版本 | sourceNodeId、sourceRevision、原文或可恢复快照引用、内容校验值 |
| 拆分草案 | schemaVersion、splitKind、识别方式/规则版本、段落映射、未归属与警告 |
| 方案组 | groupId、sourceRevision、splitOperationId、共同要求及适用成员、成员顺序 |
| 方案成员 | 稳定 itemId、标题、原文引用、可编辑正文、自身 revision、显式依赖 |
| 运行记录 | itemId、输入快照/版本、模型与有效参数、请求标识、真实任务编号及状态 |
| 产出选择 | 具体 outputId 与版本、所属 itemId；新产出不能自动替换下游已选结果 |

成员身份不以标题或数组下标决定。改名和排序不创建新身份。运行记录优先引用现有任务系统，不复制出第二套账务或任务真相。

## 7. 连线与规则生效

来源关系仅用于追溯；生成输入关系必须明确引用目标内容和版本。两种关系在数据上区分，界面选中时显示“来源/使用内容”，不能仅靠颜色辨别。旧连线维持旧语义，不批量重解释。

生成输入 = 经权限允许的已有通用规则 + 当前组适用要求 + 当前方案正文/专属要求 + 明确选择的参考资料。

本工单只新增方案组共同要求与成员引用，不自动新建全站/项目规则系统。已有全站或项目规则在明确接口和权限下复用。抽取出的“统一要求”最多默认归当前组，绝不能自动升级为全站规则。

参数类约束按字段约定覆盖顺序，锁定要求不允许覆盖；自由文本不承诺模型能够可靠裁决矛盾，发现冲突时让用户确认。受保护规则只显示来源和已应用状态，不向无权用户展示内容。

提交前可查看“本次使用内容”，包含方案、共同要求范围、具体参考资产及版本。禁止按任意上游递归遍历，把其他方案或历史产出全文一并加入。

## 8. 运行与结果闭环

单分支生成复用现有入口。批量生成仅处理用户勾选的成员，列出各自有效模型、参数、数量、真实报价或费用未知状态；不为统一批次偷偷覆盖成员设置。

提交时冻结输入，服务端重新核对项目/资产权限、可用能力、版本与价格。价格变化要求重新确认。当前生成链路不支持可靠幂等或任务恢复时，先补对应能力或暂缓批量入口，不能扩大扣费规则。

每个成员独立记录待提交、提交中、已受理、运行中、成功、失败或提交结果待确认。网络超时先用请求标识查已有任务，不立即再发。刷新恢复查询，不恢复执行按钮动作。

批次允许部分成功；保留已成功产出，只对明确失败项重新确认并重试。单次请求防重复与用户主动再次生成使用不同标识语义。停止排队项与取消已运行任务分开，供应商不支持取消时不得假报已取消。

对比视图按成员展示结果与缺失状态，用户明确选定具体产出后继续制作。历史产出保留。此版不自动判断哪项最优、不自动开启下一阶段付费操作。

## 9. 变更、撤销与删除

- 上游原文更新：提示受影响成员；使用原版本、当前用户修改及新来源做差异预览。冲突由用户选择，不按标题模糊匹配后覆盖。
- 共同要求或参考图更新：仅标记受影响分支；历史结果仍显示其生成版本，不自动改历史、不自动重新扣费。
- 运行中修改：当前任务继续使用提交快照；修改用于下一次运行。
- 再次拆分：同一来源版本、同一确认操作幂等返回已有组；用户明确选择“更新原组/另建一组”时分别处理。
- 撤销：尚未执行下游任务时可一次撤销本次创建。已有任务或结果时，只撤销可安全撤销的画布操作，说明不会撤销费用或外部任务，不删除运行证据。
- 删除：预览关联影响。删除来源可保留成员及来源快照；删除成员不自动删除资产、历史任务或其他分支共用引用。
- 保存失败：明确未保存，保留草稿和重试入口。重新打开恢复工作现场，不自动拆分、提交或重试。

## 11. 验收标准

以下是实施后的人工验收清单，不是本轮已执行测试。遵循项目用户手动验收规则；自动功能测试、真实付费生成及数据库迁移需对应明确授权。

| 场景 | 必须观察到的结果 |
|---|---|
| 图示四方案＋统一要求 | 得到四个成员；共同要求单独管理，不产生第五方案，不漏正文 |
| 编号步骤、嵌套列表、重复标题 | 不误切成独立方案；成员身份不依赖标题 |
| 无标题、混合文本、单方案 | 有待确认/手动路径；不硬凑多个方案，不编造正文 |
| 部分内容选中、用户排除成员 | 作用范围明确，未选择原文保留；排除不当作遗漏 |
| 跨方案角色引用、局部例外 | 仅传指定内容，其他方案不串入；冲突可见 |
| 无权参考资料或隐藏规则 | 拒绝越权读取；不泄露内部规则，不改变权限 |
| 新生成文本后再修改 | 不使用旧结构拆新内容；原结构失效明确 |
| 双击确认、刷新、超时 | 不重复建组或任务，不自动重发生成 |
| 批量中一项失败 | 成功项保留，只重试失败项，消耗按真实执行显示 |
| 上游修改、手改分支、运行中修改 | 有差异与版本提示；手改不被覆盖，运行快照不变 |
| 多次产出与选用 | 下游固定读取明确选定版本，不自动切为最新 |
| 撤销、删除、旧画布 | 不连带删除资产/任务；旧文档保持可读，影响可预知 |

首版必达：结构化路径可直接展开，外部文本可无损预览拆分，歧义可手动处理；来源可追溯、规则范围可查、结果可选用、恢复不重跑。AI 识别通过样本后再开放，不能成为唯一可用路径。未闭环的 SP 项保持未完成或明确受阻，不以“上线成功”代替验收。
