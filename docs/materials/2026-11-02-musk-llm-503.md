# MUSK-503：聊天 503 与受保护图片修复

项目：video-api-debugger。基线：`32a956d4b508e085cb60defb1830176e2e43b811` / v0.127.0；目标版本 v0.127.1，分支 `codex/musk-llm-503-20261102`。

## 目标与边界

修复 `/api/llm/chat` 遇到 Musk HTTP 503 时只显示状态码、本人站内上传图片被上游直接拉取而失败的问题。保留原模型白名单、登录态、普通外部图片 URL、已有文本调用方和私密提示词发送保护；不改数据库、点数、任务回执或供应商配置。

本轮明确不调用真实 Musk、聊天页面或“反推”功能，不做收费请求、浏览器功能验收或生产业务写入。工程检查只使用合成响应、合成图片字节和本地静态/构建链；功能由用户手动验收。

## 根因与架构判断

- `createMuskChatCompletion` 和 `openMuskChatStream` 在非 2xx 时丢弃上游正文，只返回 `HTTP 503`，无法看见 `error.message`、字符串 `error`、顶层 `message` 或纯文本原因。
- 聊天路由把站内 `/uploads/...` 地址直接交给 Musk。受保护资源需要当前账号权限，上游不能复用 SD2 登录态；同时旧文本兜底会再次写入同一 URL。
- `createMuskChatCompletion` 是 7 个文本入口共用层：聊天、模板工作流、模板/模块构建、角色描述、无限画布和管理员连通性测试都会使用它。一次短重试属于共享传输修复，统一作用于这些入口；流式传输当前只有聊天调用。
- 图片读取是聊天专属输入准备，不放进共享 Musk 传输层。服务器只对当前账号的 `active image` 资产按 ID/规范化上传路径双重核对，读取元数据及实际字节均限制单张 8MB，再生成 data URL；外部 URL 保持原样。这样消除上游访问站内受保护 URL 的致错机制，不扩大素材权限，也不改变其他 Musk 文本调用。
- 共享重试仅覆盖 429/502/503/504，等待约 2 秒后最多一次；400 等明确客户端错误不重试，调用方中止和总超时仍终止。残留边界：网关类响应不能证明原请求一定未受理；本次按工单明确采用一次有限重试，不建设请求回执平台。

CodeGraph 已为当前工作树同步到 1,716 个文件、29,137 个节点；结构查询接口因本轮 approval policy 禁止额外批准而不可调用，随后用精确调用点检索和源码核对确认上述 7 个普通调用方及单一流式入口，没有用主分支或线上索引替代当前工作树。

## 实现

- `src/lib/integrations/musk.ts`
  - 读取并归一化上游错误原因，限制 200 字；日志只记状态、归一化正文和尝试次数。
  - 普通与流式聊天对 429/502/503/504 最多重试一次，等待可被请求中止；保留总超时和既有安全发送入口。
  - mock 可注入 `fetchImpl` 与零延迟；生产默认约 2 秒。
- `src/lib/integrations/musk-chat-images.ts`
  - 新增聊天图片准备边界；规范化当前/历史 SD2 上传域名和相对路径。
  - 只读取当前账号、active、image 类型的资产，并核对请求 URL 与数据库原路径一致；检查 MIME、元数据大小和实际字节大小。
  - 本人站内图片转 data URL；外部图片继续使用原 URL；文本说明不复制 base64。
- `src/app/api/llm/chat/route.ts`
  - 普通与流式请求共同使用图片准备结果；图片权限、格式、大小和读取错误返回稳定状态码及错误码。
- `scripts/test-musk-chat.mjs` / `package.json`
  - 新增无真实网络的传输与图片 mock 检查；纯 JavaScript 脚本由 Node 直接执行。
- `package.json`、`package-lock.json`
  - 版本升到 v0.127.1。
